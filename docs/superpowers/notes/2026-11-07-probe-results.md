# Результаты проб — 2026-11-07

Пробы из раздела 8.1 спецификации. Сырые захваты лежали в `.superpowers/probe/`
(git-ignored) и выброшены; здесь — выводы, на которые дальше опирается код.

Проба: `scripts/probe-pty.mjs` поднимает настоящий `claude.exe` в pty,
шлёт блок из трёх строк, обёрнутый в `ESC[200~ … ESC[201~`, и никогда не жмёт
Enter — чтобы не потратить ход.

## 1. Исполняемый файл не ищется по PATH — ПОДТВЕРЖДЕНО, требует кода

`spawn('claude', ...)` через node-pty на Windows падает с `Error: File not found`,
хотя `claude` прекрасно находится из оболочки. ConPTY не выполняет поиск по
`PATH`/`PATHEXT` — ему нужен готовый путь к `.exe`.

**Вывод:** `Session` обязана резолвить исполняемый файл сама (PATH + PATHEXT,
плюс явный путь из настроек) до спавна. Задача 6 получает это требование;
её тест на понятную ошибку при отсутствии файла покрывает и этот случай.
Найденный на этой машине путь:
`C:\Users\user\AppData\Local\Microsoft\WinGet\Packages\Anthropic.ClaudeCode_Microsoft.Winget.Source_8wekyb3d8bbwe\claude.exe`

## 2. Bracketed paste включён — ПОДТВЕРЖДЕНО

В первых же байтах вывода TUI присутствует `ESC[?2004h` — режим bracketed paste
включается самим CLI. Значит обёртка `ESC[200~ … ESC[201~` — это именно тот
контракт, который он ожидает, а не наша выдумка.

**Не подтверждено пробой:** что многострочный блок складывается в один ввод,
а не в три отправки. Дойти до строки ввода проба не смогла — на старте CLI
показывает вопрос о доверии к папке, а отвечать за пользователя на вопрос
безопасности не следует.

**Вывод:** реализуем через bracketed paste (режим объявлен самим CLI).
Наша сторона контракта проверяется автотестом против подставного агента
(Задача 10). Поведение настоящего CLI проверяется человеком один раз
по релизному чек-листу (Задача 20), пункт «вставка многострочного текста».

## 3. Палитру переопределить нельзя — ОПРОВЕРГНУТО, план меняется

Ожидалось, что CLI рисует свою строку ввода номерными цветами из 16-слотовой
палитры, и мы сможем их приглушить через тему xterm. В захвате видно обратное:

```
ESC[38;2;255;193;7m   ESC[38;2;153;153;153m   ESC[38;2;177;185;249m
```

Это truecolor-RGB. Слотов палитры CLI не использует, подменять нечего.

**Вывод:** визуальная иерархия «его строка тусклая, наша яркая» из раздела 6.4
спецификации достигается не палитрой, а на уровне CSS: вся поверхность
терминала приглушается (пониженная непрозрачность), а поле ввода остаётся
полностью ярким и со свечением. Результат для пользователя тот же, механизм
другой и гораздо надёжнее — он не зависит от того, какими цветами CLI
что-то красит. Задача 7 реализует это так.

## 4. Хуки через `--settings` — НЕ ПРОВЕРЕНО пробой

Та же причина: живая сессия упирается в вопрос о доверии, а подтверждение
`Stop` требует потратить реальный ход. По документации CLI `--settings`
принимает inline JSON и переопределяет ключи только на сессию.

**Вывод:** Задача 16 строится на хуках, как и планировалось, и тестируется
против подставного агента, который умеет их звать. Запасной путь на затухание
вывода, уже заложенный в 6.9 спецификации, остаётся обязательным — именно он
закрывает риск, что хуки не доедут. Проверка против настоящего CLI — пункт
релизного чек-листа (Задача 20).

## 5. Форма интерактивного меню — наблюдение для Задачи 11

Вопрос о доверии отрисован ровно как меню выбора: маркер `❯` у активного
пункта, пункты на отдельных строках, снизу подсказка вида
`Enter to confirm · Esc to cancel`. Детектор меню может опираться на маркер
`❯` в сочетании с подсказкой про Enter/Esc.
