# Qclod v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Переписать ядро Qclod с псевдотерминала на Claude Agent SDK: одно собственное поле ввода, лента сообщений вместо экрана CLI, свои диалоги разрешений, панель состояния справа и история чатов.

**Architecture:** SDK живёт в главном процессе Electron — по одному `query()`-циклу на вкладку. Его сообщения переводятся чистой функцией в элементы ленты и уходят в рендерер через узкий preload-мост. Рендерер рисует ленту, поле ввода и панель; терминала, pty и разбора экранного вывода больше нет.

**Tech Stack:** `@anthropic-ai/claude-agent-sdk`, Electron 33, React 18, TypeScript 5, Zustand, Vitest, Playwright (`_electron`), electron-builder.

**Spec:** `docs/superpowers/specs/2026-11-07-qclod-v2-sdk-design.md`

## Global Constraints

- Платформа — Windows 11 Pro x64. Под другие ОС не собираем и не тестируем.
- SDK указывает на **исполняемый файл пользователя** (`pathToClaudeCodeExecutable` из настройки `agentPath`), а не на сборку, вшитую в SDK. Иначе версия Claude Code замораживается навсегда.
- Файлы настроек пользователя и проекта **не модифицируются никогда** — включая `.claude/settings.local.json`. Правила «разрешить всё такое» живут в хранилище Qclod.
- Настройки проекта подгружаются сразу, без вопроса о доверии — решение пользователя (спека, раздел 5). Факт наличия у папки своих хуков/MCP показывается в панели.
- Ничего не уходит с машины. Содержимое сессий Qclod не хранит и не передаёт.
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, явный список каналов — как в v1.
- Сквозные тесты гоняются только против подставного SDK, никогда против настоящего агента.
- Тема только тёмная, палитра и токены v1 без изменений.
- Сообщения коммитов короткие, без служебных подписей.

## Review Focus

Пять вещей, которые спека подразумевает, но тесты задач сами по себе не поймали бы. Тест на каждую добавлен в задачу, которой принадлежит код.

1. **Очень длинная лента.** Сессия на тысячи элементов не должна заикаться при прокрутке и дописывании (анти-цель «тормоза»). → тест в Задаче 8.
2. **Агент умер посреди ответа.** Процесс упал или был убит — прочитанное в ленте остаётся, вкладка объясняет что случилось и даёт повтор. → тест в Задаче 5.
3. **На запрос разрешения никто не ответил.** Вкладку закрыли или окно убили, пока агент ждёт `canUseTool` — обещание не должно висеть вечно и держать сессию. → тест в Задаче 6.
4. **Сессию не удалось возобновить.** Удалена, повреждена, сменилась версия CLI — вкладка открывается чистой и говорит об этом строкой, а не молча теряет разговор. → тест в Задаче 7.
5. **Пути с пробелами и кириллицей.** Скрепка, вставка файла из проводника и перетаскивание из `C:\Мои проекты\файл 1.ts` дают одно вложение, а не несколько кусков. → тест в Задаче 10.
