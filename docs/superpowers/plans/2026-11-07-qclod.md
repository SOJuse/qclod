# Qclod Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Собрать десктопное окно для Windows 11, внутри которого в псевдотерминале живёт настоящий Claude Code CLI, с вкладками, собственным полем ввода, работающими хоткеями, вставкой картинок, уведомлениями и вызовом по глобальному хоткею.

**Architecture:** Electron, два процесса. В главном — по одному pty на вкладку (node-pty), запуск `claude` с рабочей папкой вкладки, приём событий хуков через локальный именованный канал, хранение настроек и состояния вкладок. В рендерере — React, xterm.js рисует поток pty, собственное поле ввода отправляет текст как bracketed paste. Вся логика принятия решений по клавишам, режиму проброса, истории и детекции меню вынесена в чистые модули без Electron и DOM, чтобы покрываться юнит-тестами.

**Tech Stack:** Electron 33+, electron-vite, React 18, TypeScript 5, node-pty 1.0+, @xterm/xterm 5.5+ (аддоны fit / search / webgl), Zustand, Vitest, Playwright (`_electron`), electron-builder (NSIS).

**Spec:** `docs/superpowers/specs/2026-11-07-qclod-design.md`

## Global Constraints

- Платформа — Windows 11 Pro x64. Под другие ОС не собираем и не тестируем.
- `claude` уже установлен в системе; путь к нему настраивается, по умолчанию берётся из PATH.
- Релиз — NSIS `.exe`, без подписи кода. Автообновления нет.
- Ничего не уходит с машины. Содержимое сессий не хранится и не передаётся.
- **Файлы настроек пользователя (`~/.claude/settings.json`, `.claude/settings.json`) не модифицируются никогда.** Конфигурация сессии подаётся только через `claude --settings <inline JSON>`.
- Терминал всегда виден целиком. Никакой элемент интерфейса не перекрывает область вывода pty.
- Тема только тёмная. Токены: фон `rgba(14,16,28,.72)` поверх acrylic, акцент `#6E8BFF`, свечение `#B07CFF`, границы 1px низкой непрозрачности, шрифт Geist Mono — файл шрифта лежит в репозитории, из сети ничего не тянем.
- Глобальный хоткей по умолчанию `Ctrl+Shift+Space`, настраивается.
- `contextIsolation: true`, `nodeIntegration: false`, у preload явный список каналов.
- Сквозные тесты гоняются только против подставного агента из `tests/fixtures/fake-agent`, никогда против настоящего `claude`.
- Сообщения коммитов короткие, без служебных подписей.

## Review Focus

Пять вещей, которые спецификация подразумевает, но ни одна задача не проверяет сама собой. Тест на каждую добавлен в задачу, которой принадлежит код.

1. **Огромная вставка.** Текст в несколько мегабайт из буфера не должен вешать рендерер или переполнять запись в pty. → тест в Задаче 8.
2. **Пути с пробелами и кириллицей.** Drag&drop и `@`-упоминание файла `C:\Мои проекты\файл 1.ts` должны давать путь, который CLI прочитает, а не рассыпаться по пробелу. → тесты в Задачах 14 и 15.
3. **Глобальный хоткей занят.** `globalShortcut.register` возвращает `false`, если комбинацию держит другое приложение. Пользователь должен это увидеть, а не гадать, почему окно не всплывает. → тест в Задаче 17.
4. **Выход при живых сессиях.** Закрытие приложения обязано убить все процессы `claude`; осиротевших процессов остаться не должно. → тест в Задаче 6.
5. **Мусор в канале хуков.** В именованный канал может прийти неразобранный JSON или событие от вкладки, которую уже закрыли. Это не должно ронять главный процесс. → тест в Задаче 16.
