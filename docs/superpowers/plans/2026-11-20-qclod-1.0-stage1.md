# Qclod 1.0 — этап 1: стабильность и очередь. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Окно больше не гаснет в серый экран. Сообщения, отправленные во время работы агента, доходят до него между шагами, у каждого есть «Отправить сейчас», «Отменить» и «Изменить». Клик по второй панели сплита не переставляет панели.

**Architecture:**
- Сообщения уходят в Claude Code сразу, с `uuid`, `priority` и `origin`. Очередью управляет сам CLI.
- Qclod ведёт `outbox` — ещё не прочитанные агентом сообщения — по кадрам `command_lifecycle`. Отмена и «сейчас» идут через `cancelAsyncMessage` и `interrupt({cancelQueued})`.
- От серого экрана три слоя: границы ошибок React (корень и панель), присмотр main за процессом окна, журнал ошибок в `userData/logs`.
- Сплит хранит упорядоченный список панелей отдельно от активной.

**Tech Stack:** Electron 33, React 18, zustand, TypeScript, vitest, Playwright, `@anthropic-ai/claude-agent-sdk` 0.3.319, у пользователя CLI 2.1.317.

**Spec:** `docs/superpowers/specs/2026-11-20-qclod-1.0-design.md`, этап 1 (1.1–1.3). Детали очереди: `.superpowers/research/05-sdk-capabilities.md` §1–2, §7 — в основной копии `C:\Users\sojuse\qclod`, папка вне git.

1. **Сообщение отправлено, пока висит карточка разрешения.** `'next'` не вливается до ответа. Ожидание: сообщение стоит в плашке, после ответа приходит `started`, пузырь один. Тест — в задаче 6.

  export class Outbox {

- Produces, `AgentSession`:

  - `cancelQueued(id: string): Promise<UserInput | null>` — вместо `boolean`;
  - `sendQueuedNow(id: string): Promise<boolean>`;
  - `interrupt(): Promise<UserInput[]>` — прежняя;
  - `takeQueue(): UserInput[]`, `requeue(inputs)` — прежние, работают на outbox.

Поведение:
1. **Агент ещё запускается** (драйвера нет): сообщение получает `state: 'waiting'` и `canSendNow: false`, `MAX_QUEUED` прежний. Когда драйвер готов, все ожидающие уходят в CLI сразу, по порядку, каждое со своим uuid. Это замена `sendQueued` по одному за ход.
2. **Хода нет:** как сейчас — сразу пузырь (`builder.addUser`), `turn += 1`, `turnRunning = true`, отправка с uuid. В outbox не попадает.
3. **Ход идёт, режим `'cli'`:** отправка с uuid без `priority` (CLI считает `'next'`). Запись в outbox со `state: 'sending'`. Пузыря нет.
   - `command_lifecycle` `queued` — `state: 'queued'`.
   - `started` — убрать из outbox, `emit(builder.addUser(input.text, shown, composed))`. Если хода не было — `turn += 1`, `turnRunning = true`, статус `busy`.
   - `cancelled`: если `requestedCancel` — убрать; если uuid незнакомый — игнорировать; иначе — убрать и добавить notice «Сообщение не дошло до агента: ход прервали» с текстом сообщения.
4. **Ход идёт, режим `'local'`** (старый CLI): отправка сразу с uuid, CLI сам вольёт. Пузырь сразу, как в п.2. В outbox не попадает: кнопок у такого сообщения нет.
5. **`result`:** `turnRunning = false` и `idle` только если `queued_turn_count` равен 0 или отсутствует и в outbox нет записей в `sending` или `queued`. Иначе статус остаётся `busy`. `sendQueued()` в режиме `'cli'` не вызывается. Если проба (задача 2) показала кадры `system/session_state_changed`, то их `idle` и `running` — главный сигнал статуса, а `result` — запасной.
6. **`cancelQueued(id)`:** `state: 'cancelling'`, `requestedCancel = true`, затем `driver.cancelQueued(uuid)`:
   - `true` — убрать и вернуть `input`;
   - `false` — вернуть прежнее состояние и `null` (сообщение уже ушло, придёт `started`);
   - `null` — `null`.
7. **`sendQueuedNow(id)`:** `driver.cancelQueued(uuid)`:
   - `true` — отправить заново с новым uuid и `priority: 'now'`, запись в outbox под новым uuid;
   - `false` — ничего, ответ `false`;
   - `null` — `driver.interrupt()` без флага: сообщение уже в очереди CLI и пойдёт сразу после прерывания; ответ `true`.
8. **`interrupt()` («Стоп»):** `driver.interrupt({cancelQueued: true})`. Каждый uuid из `receipt.cancelled` найти в outbox, убрать и вернуть их `input` (с `withoutCopiedBytes`, как сейчас). Если `receipt` undefined — `driver.cancelQueued` по каждому из outbox, вернуть снятые. Остальная логика `interrupt` (`cancelWaits`, `stopsInFlight`) — без изменений.
9. **Смерть процесса** (`takeQueue` при замене сессии): все записи outbox — это непринятые сообщения, CLI потерял свою очередь. Они переходят в новую сессию через `requeue` ровно один раз.
10. **IPC** в `agentIpc.ts`:
    - `agentQueueCancel` возвращает `UserInput | null` (с `withoutCopiedBytes`);
    - `agentQueueSendNow(id, queuedId)` возвращает `boolean`;
    - оба принимают только строки.
