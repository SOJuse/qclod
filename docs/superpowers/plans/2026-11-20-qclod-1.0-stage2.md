# Qclod 1.0 — этап 2: новый интерфейс и брендинг. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Окно без вкладок сверху: слева проекты и их чаты (живые сверху, прошлые ниже), по центру лента колонкой 800 px и плавающее поле ввода, сплит до 4 панелей с перетаскиванием и сохранением раскладки, Ctrl+K по всему, тихая лента со сжатыми действиями, карточки вопросов/планов/разрешений закреплены над полем ввода, новая иконка a-orbit, трей с точкой статуса, экран загрузки и страница «окно не стартует».

**Architecture:**
- «Чат» — это нынешняя вкладка (`TabState`), без нового понятия в main. Проект — папка чата; список проектов и раскладка (панели, ширины, свёрнутость) живут в main в `userData/layout.json` и переживают перезапуск. Прошлые сессии проекта читаются тем же `SessionHistory.list(cwd)`.
- Окно собирается заново из готовых частей: боковая панель (`Sidebar`), сетка панелей (`SplitView`), панель чата (`ChatPane` с шапкой, лентой, плавающим доком ввода и своей правой панелью). Лента, переводчик `shared/ribbon.ts` и логика `Composer` сохраняются; меняется показ.
- Карточки уходят из ленты в закреплённую плашку над полем ввода (`PinnedCards` → `PinnedCard`). Ответ из окна несёт только выбор и тексты; `updatedInput` и правила собирает main.
- Брендинг: один мастер-SVG и один SVG-глиф трея в репозитории; `scripts/make-icon.mjs` растрирует их (`@resvg/resvg-js`) в PNG/ICO/ICNS и в маску трея, зашитую в TS-модуль. Трей красит глиф под тему панели задач и рисует точку статуса.

**Tech Stack:** Electron 33.4, React 18, zustand 5, TypeScript, vitest, Playwright, `@anthropic-ai/claude-agent-sdk` 0.3.319 (CLI у владельца 2.1.317), lucide-react, Inter + Geist Mono (уже в пакетах), новый devDependency `@resvg/resvg-js`.

## Решения автора плана

Спек и ответы этого не решают, а план от этого зависит:

1. **Строки чатов в боковой панели сохраняют `data-testid="tab"`, `.is-active`, `.tab-status.is-<статус>`, `.tab-title`, `tab-remote`, `tab-badge`, `tab-new`** — почему: на них стоит 15 e2e-файлов; смысл строки не изменился (живой чат = прежняя вкладка).
2. **Раскладка хранится в main (`userData/layout.json`), а не в `sessionStorage`** — почему: E7 требует пережить перезапуск, а main и так решает, каким чатам запускать процесс. `uiPersist` оставляет только черновики и вложения; панели из него уходят (тест «старое splitTabId» удаляется сознательно).
3. **Проект не исчезает, когда закрыт его последний чат.** «Убрать из списка» есть в меню проекта без открытых чатов. Окно по-прежнему никогда не пустое: закрыт последний чат вообще — открывается новый чат в папке закрытого (раньше — `defaultCwd`) — почему: инвариант «всегда есть активная вкладка» держит весь App и e2e.
4. **Экран истории удаляется.** Прошлые сессии — в боковой панели под проектом (5 новых, «Показать ещё» +20). Ctrl+H открывает Ctrl+K с разделом «Прошлые разговоры» — почему: поиск по истории (K4) уже есть в палитре, второй экран не нужен.
5. **Порядок Ctrl+Tab и Ctrl+1…9 — порядок строк чатов в боковой панели** (по проектам) — почему: так видит пользователь.
6. **Закреплённая плашка показывает и карточки сабагентов** (с подписью «от агента <тип>»), по одной, старшая первой, со счётчиком «Ещё N ждут ответа» — почему: разрешение сабагента иначе ждёт внутри свёрнутой карточки агента.
7. **Вариант + комментарий — одно поле под вариантами.** Ничего не выбрано — это «Свой ответ…»; выбран вариант — то же поле становится «Комментарий к «<вариант>» (необязательно)». Кодировка: `annotations[q].notes` или запасная строка «Вариант — комментарий»; какая — решает проба (задача 18), до неё по умолчанию запасная — почему: запасная работает на любом CLI.
8. **Клавиши разрешения: 1 «Разрешить» (и Enter), 2 «Разрешить всё такое», 3 «Разрешить до конца сессии», 4 «Запретить» (и Esc).** «Запретить» сначала открывает поле причины, Enter в нём отправляет (пустое — можно). Буква A убирается — почему: C6 «как Claude Code CLI», цифры не зависят от раскладки.
9. **«До конца сессии» = до закрытия процесса этого чата:** «Начать заново», «Закрыть чат», перезапуск после падения, выход из Qclod. Правило в памяти `PermissionBroker` по `tabId`, на диск не пишется.
10. **Правая панель (2.3):** «Контекст» (шкала и разбивка), «Лимиты» (5 ч и неделя со сбросом), «MCP» (сначала проблемные, подключённые свёрнуты в «N подключено»), «Remote Control», внизу строка «Сессия»: модель, стоимость, настройки проекта. Список агентов из панели уходит (он есть в `NowLine`, а слой «Агенты» — этап 4). **Строка статуса:** слева режим, модель, усилие, Remote Control; справа шкала контекста, фоновые задачи; лимиты — только плашкой-предупреждением при ≥ 80 %. Ориентир — Claude Code Desktop: usage по кнопке, а не постоянно на виду.
11. **Своя правая панель у каждой панели сплита:** прикреплена справа, если ширина панели ≥ 760 px, иначе выезжает поверх правого края панели и закрывается по Esc или клику мимо.
12. **Сжатие ленты:** подряд идущие вызовы верхнего уровня одной категории (`toolCategory`), от двух и больше, — одна строка. Размышления между ними группу не рвут и показываются внутри неё при раскрытии; текст агента рвёт.
13. **Трей:** точка — «ждёт тебя» важнее «ошибка», та важнее «работает». Тема панели задач — из реестра `SystemUsesLightTheme` (событие — `nativeTheme 'updated'`); запасной вариант — `nativeTheme.shouldUseDarkColors`. В Electron 33 нет `shouldUseDarkColorsForSystemIntegratedUI`, а `shouldUseDarkColors` на Windows следует теме приложений, не панели задач.
14. **Растр иконок — `@resvg/resvg-js` (devDependency, точная версия); маска трея зашивается в сгенерированный `src/main/brand/trayGlyph.ts`** — почему: трей остаётся без зависимости от файлов в asar, как сейчас. Белый трей-SVG варианта содержит ошибку маски (вырез залит `#fff`), поэтому берётся один чёрный глиф, тон задаётся кодом.
15. **Страница «окно не стартует» — отдельная статическая `fallback.html` без React** (второй вход сборки renderer) — почему: если падает бандл окна, страница на нём же не поможет.
16. **Кнопка «Агенты» в шапке чата не рисуется, пока этап 4 не передаст `onOpenAgents`;** слой `PaneLayer` готов и пуст — почему: пустой слой пользователю не нужен.
17. **Файл в Ctrl+K вставляет `@путь` в поле ввода активного чата;** проект — открывает его последний живой чат, а если его нет — новый чат в нём.
18. **Минимальная ширина панели сплита — 320 px;** если окно уже, ряд панелей прокручивается вбок. Боковая панель — 260 px, сворачивается Ctrl+B, свёрнутость хранится в раскладке.

## Global Constraints

Из спека §3, дословно:
- Файлы настроек пользователя Claude Code (`~/.claude`, `.claude/settings*.json`) Qclod не меняет. Всё своё хранится в `userData`.
- Автотесты никогда не ходят в настоящего агента: только фейковый SDK `tests/fixtures/fake-sdk`. Пробы на живом CLI — отдельные скрипты `scripts/probe-*.mjs`, запускаются вручную.
- Тестовые лазейки только под `__QCLOD_TEST_SEAMS__`, релизная сборка их не содержит (`src/main/buildFlags.d.ts`).
- Всё, что приходит из окна по IPC, проверяется в main (`src/main/tabs/sanitize.ts`, `src/main/agentIpc.ts`).
- Qclod запускает Claude Code пользователя, а не версию, зашитую в SDK. Каждую новую возможность CLI проверять на лету (`claude_code_version`, `capabilities` в `system/init`) и иметь запасное поведение.
- Режим «без проверок» и «авто-да» включаются только через нативное подтверждение (`confirmBypass`, `confirmAutoAllow` в `src/main/index.ts`). Это не менять.
- Ключ роутера ИИ лежит в `.superpowers/secrets/routerai.env` (вне git). В код, коммиты и логи он не попадает.
- Юнит-тесты по ходу работы; E2E перед релизом; в конце всей работы — внимательный полный проход по каждому этапу (L5).

Свои:
- Интерфейс только русский; тексты — точными строками из плана. Только тёмная тема.
- Новых пользовательских настроек этап не добавляет (анти-цель A10). Раскладка, свёрнутость и ширины — состояние окна, не настройки.
- `styleRules.test.ts` и `tokens.test.ts` зелёные: в CSS компонентов нет цветовых литералов, градиентов и `backdrop-filter` (плавающий док — непрозрачная поверхность с тенью `--shadow-menu`), в TSX нет инлайн-цветов, скругления — `--radius-*`, шрифты — шкала `--text-*`. Марка в окне — файл `src/renderer/assets/mark.svg` через `<img>`, не инлайн-SVG в TSX.
- Анимации мягкие: `--dur-fast` / `--dur` и `--ease`; при `prefers-reduced-motion: reduce` переходы выключены (одно правило в `tokens.css`).
- Каналы IPC этапа — одной группой с комментарием `// — этап 2 …` в `src/shared/channels.ts`, методы preload — одной группой.
- Ответ на карточку из окна никогда не несёт `updatedInput`: окно шлёт выбор и тексты, main строит ввод инструмента из того, что хранит сам.
- По ходу — только свои тесты (`npx vitest run <файл>`). Перед сдачей задачи — `npm run typecheck`, полный `npx vitest run`, `npm run check:seams`. Затронутые e2e-файлы — `npm run build:e2e && npx playwright test <файлы>`. Полный e2e — один раз, в задаче 19.
- Ожидания e2e меняются только сознательно: в отчёте задачи перечислить каждый изменённый тест и почему.
- Под `.superpowers/secrets` ничего не читать.

## Ручная проверка на живом CLI

Исполнитель проверки прогоняет на сборке из `stage2` с настоящим Claude Code (2.1.317 или новее), в папке-песочнице:

1. **Проекты и чаты.**
   - Открыть две папки по два чата. Закрыть один — его процесс исчез из диспетчера задач Windows, разговор появился в «Прошлые» своего проекта.
   - Клик по нему — тот же разговор продолжается (агент помнит, о чём говорили).
2. **Перезапуск.** Сплит из трёх чатов, ширины потянуты, боковая панель свёрнута. Выйти из Qclod через трей и запустить снова — та же раскладка; процессы есть у всех трёх панелей и ни у одного другого чата.
3. **Сжатие ленты.** «Прочитай все .ts файлы в src и скажи, сколько в них строк» — одна строка «Прочитал N файлов», по клику видны вызовы; размышления свёрнуты.
4. **Разрешения.**
   - В обычном режиме «создай файл x.txt» — карточка над полем ввода; `4`, причина «назови notes.txt», Enter — агент создаёт notes.txt.
   - Затем «допиши строку в notes.txt» → `3` («до конца сессии»); ещё одна правка того же файла идёт без карточки.
   - «Начать заново» — снова спрашивает.
5. **Вопросы.** «Спроси меня тремя вопросами про будущий проект» — вопросы идут по одному; цифры выбирают; на втором — выбор и комментарий; на третьем — свой ответ. Агент в ответе упоминает комментарий и свой ответ.

7. **Сабагент.** «Запусти сабагента Explore, пусть он создаст файл y.txt» — карточка над полем ввода с подписью «от агента Explore»; ответ доходит.
8. **Трей.**

   - Сменить тему Windows (Параметры → Персонализация → Цвета → режим Windows) — глиф меняет тон без перезапуска.
