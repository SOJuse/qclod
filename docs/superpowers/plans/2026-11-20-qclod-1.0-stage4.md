# Qclod 1.0 — этап 4: сабагенты. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Кнопка «Агенты» в шапке чата открывает поверх ленты граф и таймлайн сабагентов этого чата, живые и у прошлых разговоров. Клик по узлу открывает ленту сабагента как отдельный чат. В неё можно писать (через главного агента), её можно остановить. Фоновые агенты и фоновые команды собраны в одном «диспетчере задач».

**Architecture:**
- Main включает `forwardSubagentText`, `agentProgressSummaries` и `perTaskStopAffordance`. Переводчик `src/shared/ribbon.ts` раскладывает сообщения сабагентов по их карточкам. Привязка идёт по `agent_id`, затем по `parent_tool_use_id`. Возобновлённый сабагент — тот же узел.
- Граф, таймлайн и лента сабагента в окне — чистые функции от уже имеющихся `RibbonItem[]` вкладки. Новых потоков данных из main для них нет.
- Писать сабагенту — это обычное сообщение главному агенту с поручением «через SendMessage». Сообщение несёт метку `relay`, лента показывает его как переписку с сабагентом.
- Остановка: `stopTask`. Для агента на переднем плане — `backgroundTasks(toolUseId)` и затем `stopTask` (точный путь — по пробе, задача 1).
- Прошлые разговоры читает `transcript.ts`, который уже подмешивает файлы `subagents/agent-*.jsonl`. Он дополняется отметками времени и вложенными агентами.

**Tech Stack:** Electron 33, React 18, zustand, TypeScript, vitest, Playwright, `@anthropic-ai/claude-agent-sdk` 0.3.319, у пользователя CLI 2.1.317. Новых зависимостей нет.

**Spec:** `docs/superpowers/specs/2026-11-20-qclod-1.0-design.md`, этап 4 (4.1–4.5), §3, §7. SDK — `.superpowers/research/05-sdk-capabilities.md` §3, проба очереди — `05a-queue-probe.md` (обе в `C:\Users\sojuse\qclod`, вне git). Типы — `node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts`, `sdk-tools.d.ts`.

## Решения автора плана

1. **Форма экрана (спек 4.1, «решение исполнителя»).** Слой `AgentsLayer` закрывает только ленту своей панели. Закреплённые карточки (этап 2) и поле ввода остаются видны. Вопрос главного агента не должен прятаться за графом. В ленте сабагента поле ввода чата на время заменяется полем сабагента на том же месте. Черновик чата хранится в store и не теряется. Esc закрывает слой. *Почему:* модалка закрыла бы карточки вопросов, а второе поле ввода рядом с первым путает.
2. **Рисование графа: SVG вручную, без библиотеки.**
   - Узлы — HTML-кнопки в абсолютной раскладке: перенос и обрезка текста, фокус, доступность.
   - Связи — один слой `<svg>` с кривыми.
   - Раскладка — своё дерево слева направо, около 80 строк.

   *Почему:* у владельца 10–15 узлов, и это всегда дерево (главный → сабагенты → вложенные). dagre (не развивается) и elkjs (~1,3 МБ) решают общий граф, которого здесь нет. Спек просит держать зависимости лёгкими.
3. **Прошлые разговоры — через `transcript.ts`, а не `getSubagentMessages`/`listSubagents`.** `transcript.ts` уже читает `subagents/agent-<id>.jsonl` целиком, со структурным выводом инструментов. `getSubagentMessages` отдаёт урезанную цепочку, как `getSessionMessages`: из-за этого `transcript.ts` когда-то и появился. Id агентов берутся из `toolUseResult.agentId` и `agent-*.meta.json`, а `listSubagents` даёт только список id. *Почему:* один путь нормализации для живой ленты и истории, ничего нового на диске.
4. **Писать работающему сабагенту на переднем плане.** Такой агент держит вызов `Agent` главного, и граница шагов не наступит, пока он не кончит. Сообщение `'next'` ждало бы до конца его работы. Поэтому сначала `backgroundTask(toolUseId)`, затем поручение с `priority: 'next'`. Если увести в фон не вышло (`false`/`null`/ошибка) — поручение с `priority: 'now'` и `origin: human`: CLI сам уведёт в фон то, что можно. Спек говорит `'next'`. Отступление — только для этого случая, иначе F5 («прямо во время работы») не выполняется.
5. **Текст поручения** (точная строка, `src/main/agent/subagentRelay.ts`):
   ```
   Передай агенту <ref> через SendMessage (to: "<ref>") это сообщение от пользователя, дословно:

   <текст>
   ```
   `<ref>` — `agentId`, иначе `taskId`, иначе имя из `AgentInput.name`. Слова «от пользователя» добавлены из-за park P1 этапа 1: haiku однажды принял влитое сообщение за инъекцию.
6. **`perTaskStopAffordance: true`.** Qclod теперь рисует кнопку остановки у каждой фоновой задачи. С этим объявлением «Стоп» прерывает только ход, а фоновые агенты живут дальше, как в терминале (sdk.d.ts:4797). Чтобы 15 агентов не останавливать по одному, в диспетчере задач есть кнопка «Остановить все».
7. **Стоимость сабагента (F10) — оценка без таблицы цен.**
   - Средняя цена токена модели берётся из `result.modelUsage[модель].costUSD / сумма токенов` этой же сессии. Она умножается на токены агента.
   - Подпись: «≈ $0.0421» (формат `usd` — тот же, что у стоимости сессии в панели).
   - У разговора из истории до первого хода `result` нет — показывается «стоимость неизвестна».

   *Почему:* таблица цен в коде устаревает с каждой моделью. `modelUsage` считает сам CLI, и сабагенты там учтены.
8. **Сообщения, которые CLI пересылает из разговора сабагента с ролью `user`** (его промпт, доставки SendMessage), отдельными пузырями не рисуются.
   - Промпт берётся из `AgentInput.prompt` и стоит вверху ленты сабагента.
   - Доставки берутся из вызова `SendMessage` главного агента.

   *Почему:* один источник без дублей, и он работает даже на CLI без `forwardSubagentText`.
9. **Прямого пути «написать сабагенту» в CLI 2.1.317 нет** (05 §3.2). Маршрут выбирает одна функция `subagentRoute(init)`, сейчас она отдаёт `'main' | 'none'`. Скрипт-проба печатает все `capabilities` с «agent» в имени, которых нет в известном списке. Появится прямой путь — меняется одна функция и добавляется ветка драйвера.
10. **Диспетчер задач остаётся всплывающим списком в строке статуса** (компонент `BackgroundTasks`, место ему даёт этап 2), а не вкладкой слоя «Агенты». Строки агентов в нём открывают ленту агента в слое.
11. **Новых настроек нет** (анти-цель §2). `forwardSubagentText`, `agentProgressSummaries` и `perTaskStopAffordance` включены всегда. Старый CLI неизвестные поля `initialize` игнорирует.

## Global Constraints

Из спека §3, дословно:
1. Файлы настроек пользователя Claude Code (`~/.claude`, `.claude/settings*.json`) Qclod не меняет. Всё своё хранится в `userData`.
2. Автотесты никогда не ходят в настоящего агента: только фейковый SDK `tests/fixtures/fake-sdk`. Пробы на живом CLI — отдельные скрипты `scripts/probe-*.mjs`, запускаются вручную.
3. Тестовые лазейки только под `__QCLOD_TEST_SEAMS__`, релизная сборка их не содержит (`src/main/buildFlags.d.ts`).
4. Всё, что приходит из окна по IPC, проверяется в main (`src/main/tabs/sanitize.ts`, `src/main/agentIpc.ts`).
5. Qclod запускает Claude Code пользователя, а не версию, зашитую в SDK. Каждую новую возможность CLI проверять на лету (`claude_code_version`, `capabilities` в `system/init`) и иметь запасное поведение.
6. Режим «без проверок» и «авто-да» включаются только через нативное подтверждение (`confirmBypass`, `confirmAutoAllow` в `src/main/index.ts`). Это не менять.
7. Ключ роутера ИИ лежит в `.superpowers/secrets/routerai.env` (вне git). В код, коммиты и логи он не попадает.
8. Юнит-тесты по ходу работы; E2E перед релизом; в конце всей работы — внимательный полный проход по каждому этапу (L5).

Свои:
- Транскрипты `~/.claude/projects/*` только читаются. Тест-страж `transcript.test.ts` «ничего не открывается на запись» остаётся зелёным.
- Из окна приходят только id карточки ленты (`cardId`) и текст, никогда `taskId`/`toolUseId`/`agentId`. Main сам находит их по своей ленте. Чужой или выдуманный id до агента не доходит.
- Интерфейс только на русском, тексты — точно как в задачах.
- Анимации — только CSS, и каждая отключается в `@media (prefers-reduced-motion: reduce)`. Смысл («работает») всегда передан ещё текстом и значком.
- Формы кадров, не снятые с живого CLI, помечаются в README фейка «не снято с живого CLI» и сверяются с пробой (задача 1) до задач 3, 10, 11.
- По ходу — только свои тесты (`npx vitest run <файл>`). Перед сдачей задачи — `npm run typecheck` и полный `npx vitest run`. Исключение — полоса L2: полный прогон один раз, в конце полосы. E2E — в задаче 17.
- Ключ роутера (`.superpowers/secrets/`) этому этапу не нужен: не читать.

## Review Focus

1. **10–15 сабагентов пишут одновременно.** Их потоковые куски (`stream_event`) приходят вперемешку, у всех `index: 0`. Ожидание: текст каждого лежит в своей карточке, ни одна фраза не уходит к соседу. Сейчас `openBlocks` ключуется только по `index`. Тест — задача 5.
2. **Возобновлённый через SendMessage сабагент.** Его сообщения несут прежний `agent_id`, но `parent_tool_use_id` может указывать на вызов `SendMessage`. Ожидание: шаги идут в старую карточку, она снова «работает», `runs: 2`, второго узла нет. Тест — задача 5.
3. **Написал работающему агенту на переднем плане.** Ожидание: сообщение доходит до главного агента сразу, а не после конца сабагента. Тест — задача 10.
4. **«Стоп», пока поручения сабагенту стоят в плашке.** Ожидание: текст поручения («Передай агенту…») не попадает в поле ввода чата. Сообщение в ленте сабагента помечено «не передано». Тест — задача 10.
5. **Вложенный агент, чьи вызовы CLI не пересылает** (есть только `task_started` с `parent_task_id`). Ожидание: узел есть и стоит под своим родителем, а не теряется и не всплывает в корень. Тест — задача 5.

## Ручная проверка на живом CLI

Исполнитель проверки прогоняет это в собранном Qclod на настоящем Claude Code владельца (opus, обычный режим, тестовая папка):

1. «Запусти три сабагента параллельно: каждый пусть прочитает по одному файлу из src и кратко опишет его». Проверить:
   - граф — три узла, дышат, связи бегут;
   - через ~30 с у узлов появляется строка сводки (`agentProgressSummaries`);
   - тексты каждого лежат в своей ленте, без смешения;
   - после конца — время и токены, «≈ $» в подробностях.
2. Открыть ленту законченного сабагента, написать «Добавь ещё одно предложение о тестах». Проверить:
   - в плашке очереди видно «→ агенту …»;
   - статусы «ждёт главного агента» → «главный агент прочитал» → «передано»;
   - узел снова работает, «запуск 2», его новый текст — в той же ленте;
   - в главной ленте пузырь «→ агенту …» и карточка `SendMessage → <id>`.
3. Сабагент на переднем плане (`run_in_background: false`, «запусти Bash sleep 120 внутри сабагента»), во время работы написать ему. Проверить:
   - агент ушёл в фон;
   - главный агент прочитал поручение сразу, не через две минуты.
4. Тот же сценарий, кнопка «Остановить». Проверить: агент остановлен, в графе «остановлен», notice «не остановился» не появился.
5. Пять фоновых агентов, «Стоп» в чате. Проверить:
   - фоновые продолжают работать (`perTaskStopAffordance`);
   - «Остановить все» в диспетчере задач останавливает все;
   - фоновая команда (`npm test` в фоне) — в том же списке.
6. Закрыть чат, открыть этот разговор из боковой панели. Проверить: граф и таймлайн с отметками времени, ленты сабагентов читаются.
7. Включить в Windows «Показывать анимацию» = выкл (reduced motion). Проверить: узлы не дышат, связи не бегут, состояние читается словом.
8. Remote Control включён, остановить фонового агента с телефона. Проверить: в Qclod узел «остановлен».
9. `npm run check:seams` и проверка, что `~/.claude/settings.json` и `.claude/settings*.json` тестовой папки не изменились (дата и хэш до и после).
