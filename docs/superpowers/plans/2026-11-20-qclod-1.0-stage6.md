# Qclod 1.0 — этап 6: Mac и SSH. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Qclod работает на MacBook M3 (DMG arm64, ad-hoc подпись, нативные «светофоры», меню «Правка», ⌘ вместо Ctrl), а на обеих платформах открывает чаты на домашнем Linux-сервере: агент живёт на сервере в посреднике Qclod, который сам отвечает по таймеру в «авто-да», ждёт лимит, перезапускает упавший процесс и не останавливается, когда Mac закрыт.

**Architecture:**
- **6a Mac** — ветки по `process.platform` в main (окно, меню, трей, жизненный цикл, PATH из оболочки входа, уведомление о версии вместо автообновления) и модуль сочетаний с `Mod` вместо `Ctrl`. Сборка DMG — отдельный job на `macos-latest`, ad-hoc подпись в `afterPack`.
- **6b SSH-ядро и посредник** — посредник `qclod-relay` (Node 22 SEA, linux-x64/arm64) живёт в `~/.qclod/` под systemd user или tmux, держит сессии Agent SDK, общее ядро автономности этапа 3, журнал с номерами и шлюз разрешений. Qclod ходит к нему по одному долгоживущему каналу `ssh -T host -- ~/.qclod/bin/qclod-relay attach` (JSON-строки). На стороне Qclod `RelayDriver` реализует тот же `AgentDriver`, поэтому `AgentSession`, `ribbon.ts` и карточки работают без изменений.
- **6c удалённый UX** — экраны подключения, выбор папки, метка и цвет сервера, аккаунт и вход, `FileViewer` с `FileSource`, @-упоминания и загрузка файлов по серверу, терминал (xterm.js + node-pty + системный ssh).

**Tech Stack:** Electron 33, React 18, zustand, TypeScript, vitest, Playwright, electron-builder 25.1.8, `@anthropic-ai/claude-agent-sdk` 0.3.319, системный OpenSSH (Windows 10.2p1 у владельца), Node 22 SEA + esbuild + postject (посредник), `node-pty` ≥ 1.1 (N-API, prebuild), `@xterm/xterm` + `@xterm/addon-fit`.

**Spec:** `docs/superpowers/specs/2026-11-20-qclod-1.0-design.md`, этап 6 (6.1, 6.2), §3, §7. Ответы владельца H и I и решения в конце — `C:/Users/sojuse/qclod/.superpowers/questionnaire/answers.md`. Исследование — `C:/Users/sojuse/qclod/.superpowers/research/04-ssh-and-mac.md` (вне git).

## Решения автора плана

1. **Посредник — Node 22 SEA, а не Bun.** Тот же рантайм, что у vitest: ядро автономности и драйвер проверены именно в Node. Сборка — на родных раннерах `ubuntu-latest` (x64) и `ubuntu-24.04-arm` (arm64), без кросс-компиляции. Задача 7 подтверждает, что SDK собирается esbuild в CJS и запускается внутри SEA.
2. **Один канал на всё.** RPC, поток агента, файлы (`fs.list/read/index/upload`) идут через `qclod-relay attach`. Обзор папок «по SFTP» (I5) сделан через посредника: подсистема SFTP на сервере не нужна, а на Windows нет ControlMaster, и каждое новое ssh-соединение — новая авторизация. До установки посредника идут только три отдельных вызова ssh: проба, загрузка бинарника, `setup`.
3. **Бинарник посредника Qclod скачивает сам** из GitHub-релиза своей версии (`qclod-relay-<ver>-linux-<arch>.gz`) в `userData/relay/`, сверяет SHA-256 со встроенным `relay-manifest.json` и передаёт на сервер через `ssh … 'cat > …'`. Серверу интернет не нужен; установщик Qclod не растёт на ~60 МБ.
4. **`~/.ssh` Qclod не меняет.** `UserKnownHostsFile="<userData>/ssh/known_hosts" ~/.ssh/known_hosts`: новые ключи пишутся в файл Qclod, ключи пользователя читаются. Отпечаток подтверждается через askpass-вопрос самого ssh, поэтому работает и для jump-хостов (`ProxyJump`).
5. **Askpass.** Windows: `SSH_ASKPASS` — сам `Qclod.exe` в режиме askpass (переменная `QCLOD_ASKPASS_PIPE`). `.cmd` не годится: текст вопроса приходит с сервера (keyboard-interactive) и прошёл бы через разбор cmd. Mac: sh-обёртка `ELECTRON_RUN_AS_NODE=1 exec "<Qclod>" "<askpass.js>" "$@"`, чтобы не мигать иконкой в Dock. Задача 7 проверяет оба пути на живом ssh.
6. **Пароли** хранятся через `safeStorage` (в Electron 33 только синхронный API) в `userData/servers.json`, зашифрованными. Пароли от ключей не хранятся никогда.
7. **Терминал сервера — выдвижная панель под лентой серверного чата** (кнопка «Терминал»), а не отдельный вид вкладки: модель вкладок этапа 2 не меняется. Выбран `node-pty` с системным `ssh -tt` (на Windows — ConPTY). Причина: только при настоящем локальном терминале ssh узнаёт об изменении размера окна и шлёт `window-change`. С `ssh -tt` поверх обычных труб размер навсегда 80×24, и `vim`/`htop` ломаются при ресайзе. Это тот же стек, что у терминала VS Code.
8. **Картинки идут в сообщении base64**, как локально, и загрузки не требуют. **Файлы** загружаются в `~/.qclod/uploads/<сессия>/` в момент прикрепления, и в сообщение попадает уже серверный путь.
9. **Посредник многоклиентный.** К нему могут подключаться ПК и Mac одновременно. Карточка разрешения приходит обоим, побеждает первый ответ.
10. **Обновление посредника.** Бинарник меняется сразу, демон перезапускается, только когда все сессии свободны. Если протокол несовместим, Qclod предлагает «Обновить сейчас» с предупреждением, что агенты перезапустятся с тем же разговором.
11. **Mac:** только DMG, без `zip` (автообновления нет). О новой версии Qclod узнаёт из `api.github.com/repos/SOJuse/qclod/releases/latest`. «История» на Mac — ⌘Y, потому что ⌘H скрывает приложение. Переключение вкладок остаётся ⌃Tab, потому что ⌘Tab — системное.
12. **CI выполняется последовательно:** relay → win → mac. Job `win` создаёт релиз через electron-builder, как сейчас. Job `mac` и загрузка ассетов посредника кладут файлы в уже созданный релиз через `gh release upload`. Так нет гонки двух jobs за создание одного релиза.
13. **Демон посредника не завершается от простоя.** Владельцу нужна работа при Mac, закрытом на неделю. Журналы закрытых сессий удаляются через 30 дней.
14. **Claude Code на сервер не ставится** (I14). Сервер на musl (Alpine) не поддерживается: официальный Node-бинарник требует glibc.
15. **`spawnClaudeCodeProcess` не используется.** Спек упоминает его для запуска агента, но решение владельца о посреднике-хосте его заменяет: SDK работает на самом сервере, и Qclod не держит stdio claude через ssh.

**Не делаем в этом этапе:** проброс портов (I16), синхронизацию серверов и настроек (I18), Linux-сборку Qclod (H10), автоустановку Claude Code (I14), автообновление на Mac (H4), голос на Mac (G11).

## Global Constraints

Из спека §3, дословно:
1. Файлы настроек пользователя Claude Code (`~/.claude`, `.claude/settings*.json`) Qclod не меняет. Всё своё хранится в `userData`.
2. Автотесты никогда не ходят в настоящего агента: только фейковый SDK `tests/fixtures/fake-sdk`. Пробы на живом CLI — отдельные скрипты `scripts/probe-*.mjs`, запускаются вручную.
3. Тестовые лазейки только под `__QCLOD_TEST_SEAMS__`, релизная сборка их не содержит (`src/main/buildFlags.d.ts`).
4. Всё, что приходит из окна по IPC, проверяется в main (`src/main/tabs/sanitize.ts`, `src/main/agentIpc.ts`).
5. Qclod запускает Claude Code пользователя, а не версию, зашитую в SDK. Каждую новую возможность CLI проверять на лету (`claude_code_version`, `capabilities` в `system/init`) и иметь запасное поведение.
6. Режим «без проверок» и «авто-да» включаются только через нативное подтверждение (`confirmBypass`, `confirmAutoAllow` в `src/main/index.ts`). Это не менять.
7. Ключ роутера ИИ лежит в `.superpowers/secrets/routerai.env` (вне git). В код, коммиты и логи он не попадает.
8. Юнит-тесты по ходу работы; E2E перед релизом; в конце всей работы — внимательный полный проход по каждому этапу (L5).

Свои:
- Интерфейс только на русском; тексты — точными строками из задач.
- `~/.ssh/*` Qclod не пишет (решение 4). На сервере Qclod пишет только в `~/.qclod/` и в собственный unit `~/.config/systemd/user/qclod-relay.service`.
- Локальное окружение на сервер не уходит: ни env, ни `ForwardAgent`, ни порты (`-o ForwardAgent=no -o ClearAllForwardings=yes`).
- Всё, что приходит от посредника, проверяется в main (`parseFrame`), как IPC. Всё, что приходит в посредник, проверяется там же. Одна строка протокола — не больше 16 МиБ.
- Пароль нигде не лежит открытым текстом: ни в файлах, ни в логах, ни в аргументах процессов. Он передаётся только через трубу askpass с одноразовым токеном.
- Код без Electron лежит в `src/core/` и `src/relay/`: тест-страж (этап 3) распространяется и на `src/relay/**`.
- `src/relay/**` не импортирует `ribbon.ts` и ничего из `src/renderer`: ленту строит Qclod.
- По ходу запускаются только свои тесты через фильтр (`npx vitest run <файл>`). Перед сдачей задачи — `npm run typecheck`, полный `npx vitest run`, `npm run check:seams`. E2E прогоняется один раз в задаче 27.
- Каждый метод, который этапы 3–5 добавили в `AgentDriver`, должен быть в `RELAY_DRIVER_OPS` (задача 8). Если не так, typecheck падает.
- Ключ роутера (`.superpowers/secrets/`) в этом этапе не нужен и не читается.

## Review Focus

1. **Связь оборвалась при открытой карточке, и пока её не было, посредник ответил сам («авто-да»).** Ожидание: после переподключения карточка закрыта с пометкой «авто». Она не висит открытой, и второй ответ не уходит. Тест — задача 19, `'ответ посредника во время обрыва закрывает карточку один раз'`.
2. **Часы Mac и сервера расходятся на минуты.** Ожидание: обратный отсчёт на карточке верный. Посредник шлёт `remainingMs`, а не время сервера. Тест — задача 18, `'дедлайн при сдвиге часов ±10 мин'`.
3. **Qclod закрыли или ноутбук уснул.** Ожидание: агенты на сервере продолжают работу. Выход из Qclod отцепляет клиента, а останавливает агента только «Закрыть чат». Тест — задача 19, `'disposeAll отцепляет, close останавливает'`.
4. **Сохранённый пароль неверен.** Ожидание: Qclod подаёт его один раз, потом спрашивает человека с текстом «Пароль не подошёл». Не зацикливается и не блокирует аккаунт повторами. Тест — задача 16, `'второй вопрос пароля в той же попытке идёт человеку'`.
5. **Обновление посредника, пока агент работает.** Ожидание: работа не прерывается, перезапуск откладывается до простоя. Тест — задача 12, `'relay.restart idle ждёт, пока все сессии свободны'`.

## Ручная проверка на живом CLI

Исполнитель проверки — на машинах владельца: ПК (Windows 11, OpenSSH 10.2), MacBook M3, домашний Linux-сервер с Claude Code, залогиненным под **другим** аккаунтом.

1. **Mac, установка.** DMG из CI → «Программы» → первый запуск → «Открыть всё равно» по README. Приложение стартует, светофоры на месте, ⌘C/⌘V/⌘A/⌘Z в поле ввода работают, значок в строке меню инвертируется в тёмной теме.
2. **Mac, PATH.** Запуск из Dock. Локальный чат находит `~/.local/bin/claude` без настройки пути. ⌘T, ⌘W, ⌘K, ⌘, работают. ⌘H прячет Qclod, ⌘Y открывает историю.
3. **Mac, версия.** Выпущен тестовый тег выше установленного → баннер «Вышла версия…» → «Скачать» открывает страницу релиза.
4. **Первое подключение с ПК.** Сервер из `~/.ssh/config` → вопрос ключа с отпечатком. Сверить на сервере `ssh-keygen -lf …` → «Доверять» → чек-лист зелёный, посредник в `~/.qclod/bin`. `~/.ssh/known_hosts` на ПК не изменился, новый ключ — в `userData/ssh/known_hosts`.
5. **Пароль.** Сервер с паролем, «Запомнить» → повторное подключение без вопроса. Сменить пароль на сервере → «Пароль не подошёл» ровно один раз, без блокировки аккаунта. Открыть `servers.json` — пароля открытым текстом нет.
6. **Чат на сервере.** Выбрать папку → чат сразу. Агент на сервере отвечает. Панель показывает почту и тариф **серверного** аккаунта. Метка и цвет сервера видны в боковой панели и шапке.
7. **Mac закрыт.** Режим «авто-да», задача на 20+ минут с вопросом агента. Выйти из Qclod на Mac. Через 5 минут посредник отвечает сам. Утром Qclod подключается: лента дочитана, ответ помечен «авто», работа продолжилась без Qclod.
8. **Обрыв.** Выключить Wi-Fi посреди хода на 2 минуты → «переподключение…» → после возврата пропущенный вывод на месте, без дублей. Отправленное во время обрыва сообщение дошло.
9. **Лимит и падение на сервере.** Убить `claude` на сервере `kill` → посредник перезапускает тот же разговор и шлёт «продолжай». Remote Control снова включён — видно в приложении Claude под серверным аккаунтом.
10. **Linger.** На сервере `loginctl disable-linger` → чек-лист показывает предупреждение с командой. После `sudo loginctl enable-linger <user>` агент переживает выход из всех ssh-сессий.
11. **Вход на сервере.** `claude auth logout` на сервере → в Qclod «Вход не выполнен» → «Войти» → ссылка, код → «Вход выполнен: <email>».
12. **Нет Claude Code.** Временно переименовать серверный `claude` → чек-лист говорит «не найден… Qclod сам его не устанавливает», ничего не ставит.
13. **Файлы.** Клик по пути из ответа → просмотр с подсветкой, «Только просмотр». «Скачать и открыть» открывает локальную копию. @-список показывает файлы сервера. Вставленный PDF загружен в `~/.qclod/uploads/…`, агент его читает. Скриншот виден агенту.
14. **Терминал.** «Терминал» → shell сервера в папке чата. `htop` при изменении размера панели перерисовывается верно.
15. **Два клиента.** Один серверный чат открыт и на ПК, и на Mac. Вопрос агента виден на обоих. Ответ на ПК закрывает карточку на Mac.
16. **Обновление посредника.** Поставить Qclod новой версии, пока агент работает → «Посредник обновится, когда агенты на сервере закончат работу». После хода демон перезапущен, разговор продолжается.
17. **Файлы Claude Code не тронуты.** На ПК, Mac и сервере `~/.claude/settings*.json` и `.claude/` проектов без изменений (сравнить хеши до и после).
