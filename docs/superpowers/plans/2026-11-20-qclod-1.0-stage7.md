# Qclod 1.0 — этап 7: шаблоны, Git-панель, просмотр файлов и выпуск 1.0. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Владелец вставляет свои шаблоны через `/` и Ctrl+K, а Claude один раз собирает их из его истории. Изменения проекта видны в Git-панели: diff и коммит с сообщением. Файлы и diff открываются только для чтения, с подсветкой. Ctrl+K ищет по тексту прошлых разговоров. После полного прохода по всем этапам Qclod выходит как 1.0.0.

**Architecture:**
- Шаблоны лежат в `userData/templates.json` (main, `TemplateLibrary`). Окно получает их по IPC и вставляет в поле ввода этапа 2 в место курсора. Вставка идёт двумя путями: группа «Шаблоны» в списке `/` и группа «Шаблоны» в Ctrl+K.
- «Собрать мои шаблоны» работает в main в два шага:
  - сначала Qclod сам, только на чтение, достаёт из `~/.claude/projects/*/*.jsonl` сообщения, набранные человеком, и показывает сводку;
  - после «Собрать» уходит один разовый `query()` через Claude Code владельца: без инструментов, без записи сессии на диск, моделью `sonnet`.
- Git — системный `git` через `execFile` с массивом аргументов. Пути идут через `--pathspec-from-file` по stdin, опасные настройки репозитория выключены `-c`. За проверки отвечает `GitService` в main: окно шлёт id вкладки, а не путь к папке, и пути только из последнего статуса. Для серверных проектов исполнитель git подменяется адаптером над удалённым exec этапа 6.
- Просмотр файлов — `FileViewer` этапа 6 (`FileSource`). Этап 7 добавляет `DiffViewer` с подсветкой и проводку локальных файлов.
- Полнотекстовый поиск по истории идёт потоково по тем же транскриптам, с кэшем в памяти. На диск Qclod ничего не пишет.

**Tech Stack:** Electron 33, React 18, zustand, TypeScript, vitest, Playwright, `@anthropic-ai/claude-agent-sdk` 0.3.319 (опции `tools`, `persistSession`, `settingSources`, `maxTurns`, `maxBudgetUsd`, `systemPrompt`), системный Git ≥ 2.25, electron-builder 25, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-20-qclod-1.0-design.md`, §5 «Этап 7» (7.1–7.3), §3, §6, §7. Ответы владельца — `C:/Users/sojuse/qclod/.superpowers/questionnaire/answers.md` (K1, K4, K6, A10, L3, L5).

## Решения автора плана

1. **Один вид сущности — «шаблон».** Сниппет — это тот же шаблон: он всегда вставляется в место курсора. Изменяемые места пишутся как `{{что подставить}}`, после вставки первое такое место выделено. Почему: A10 — не плодить понятий и настроек; выделение даёт «заполни здесь» без отдельного мастера.
2. **Шаблоны лежат в своём файле `userData/templates.json`**, а не в `settings.json`. Почему: это данные владельца, а не настройки. Битый файл не должен ни сбрасывать настройки, ни сам затираться пустым списком.
3. **Историю для «Собрать» читает Qclod, а не Claude.** Main сам выбирает только сообщения человека (без ответов, вывода команд и файлов), показывает сводку по проектам и полный список «что уйдёт». Отдаёт их одним запросом с опциями:
   - `model: 'sonnet'`, `tools: []`, `maxTurns: 1`;
   - `settingSources: []`, `persistSession: false`;
   - свой `systemPrompt`, `maxBudgetUsd: 0.5`, тайм-аут 180 с;
   - объём: последние 90 дней, ≤ 400 сообщений, ≤ 60 000 символов.

   Почему так:
   - сводка «что прочитается» точна до символа;
   - без инструментов Claude не может прочитать ничего сверх показанного;
   - `persistSession: false` — сам запрос не появится в истории владельца и не попадёт в следующий сбор;
   - Sonnet хватает для обобщения, и он дешевле Opus;
   - внешнего ключа нет: работает Claude Code владельца и его подписка.
4. **Ответ Claude — JSON-массив в тексте, разбор терпимый.** `outputFormat` не используем: структурный вывод зависит от версии CLI (ограничение 5), а разбор текста работает на любой.
5. **Git-панель — слой поверх ленты по кнопке «Git» в шапке чата**, как «Агенты» этапа 4. В слое галочки по файлам, коммит отмеченных одним сообщением. **Не делаем:** push, ветки, слияния, частичный stage по кускам, «отменить изменения». «Отменить» — это необратимая правка файлов, то есть IDE (A10). Push в спеке не назван, его делает агент или терминал.
6. **Git для серверных проектов — через удалённый exec этапа 6, если он есть** (задача 15, три исхода по порядку предпочтения). Если нет, Git-панель для сервера в 1.0 только локальная: кнопка неактивна, причина в подсказке.
7. **Полнотекстовый поиск по истории в 1.0 — да.** Почему:
   - владелец принял рекомендацию K4 «по всему тексту»;
   - чтение транскриптов уже пишется для «Собрать мои шаблоны» (задача 6), поэтому поиск — одна небольшая задача;
   - индекса на диске нет: Qclod не хранит переписку. Поиск потоковый, с бюджетом времени и кэшем в памяти.
8. **Тег `v1.0.0` — единственная остановка на владельца в этапе.** Релиз уходит друзьям автообновлением, это необратимо. Всё остальное, по указанию владельца от 20.11, делается без остановок.
9. **Сборка Mac проверяется до тега:** в `release.yml` добавляется `workflow_dispatch`, при котором сборка идёт без публикации и выкладывает файлы как artifacts.
10. **Текст релиза — `build/release-notes.md`**, подключается в `electron-builder.yml` через `releaseInfo.releaseNotesFile`. Так у задач Windows и Mac один текст, и electron-updater показывает его же.

## Global Constraints

Из спека §3, дословно:
1. Файлы настроек пользователя Claude Code (`~/.claude`, `.claude/settings*.json`) Qclod не меняет. Всё своё хранится в `userData`.
2. Автотесты никогда не ходят в настоящего агента: только фейковый SDK `tests/fixtures/fake-sdk`. Пробы на живом CLI — отдельные скрипты `scripts/probe-*.mjs`, запускаются вручную.
3. Тестовые лазейки только под `__QCLOD_TEST_SEAMS__`, релизная сборка их не содержит (`src/main/buildFlags.d.ts`).
4. Всё, что приходит из окна по IPC, проверяется в main (`src/main/tabs/sanitize.ts`, `src/main/agentIpc.ts`).
5. Qclod запускает Claude Code пользователя, а не версию, зашитую в SDK. Каждую новую возможность CLI проверять на лету (`claude_code_version`, `capabilities` в `system/init`) и иметь запасное поведение.
6. Режим «без проверок» и «авто-да» включаются только через нативное подтверждение (`confirmBypass`, `confirmAutoAllow` в `src/main/index.ts`). Это не менять.
7. Ключ роутера ИИ лежит в `.superpowers/secrets/routerai.env` (вне git). В код, коммиты и логи он не попадает.
8. Юнит-тесты по ходу работы; E2E перед релизом; в конце всей работы — внимательный полный проход по каждому этапу (L5).

Свои:
- Транскрипты `~/.claude/projects` (или `CLAUDE_CONFIG_DIR`) открываются только на чтение (`flags: 'r'`). Тест-страж в задачах 6 и 9 ловит любой открытый на запись путь.
- Тексты сообщений из истории не пишутся ни в `userData`, ни в журнал `userData/logs`. Сохраняются только шаблоны, которые отметил владелец.
- `git` запускается только через `execFile`/`spawn` с массивом аргументов, без `shell: true`. Во всех вызовах — `GIT_BASE_ARGS` (задача 10). В чтении (status, diff) ещё `--no-ext-diff` и `--no-textconv`. В окружении `GIT_TERMINAL_PROMPT=0`.
- Окно никогда не передаёт папку для git — только `tabId`. Пути для diff и коммита main принимает только из последнего статуса этой вкладки.
- Qclod не правит файлы проекта: никаких `checkout`, `restore`, `reset`, `clean`, `stash`. Из пишущих команд git — только `add` и `commit`.
- Интерфейс только на русском. Тексты — точными строками из плана.
- Каналы этапа 7 — одной группой в `src/shared/channels.ts` с комментарием `// этап 7: шаблоны, Git, поиск по истории`. Preload — тоже одной группой.
- Новых настроек нет (A10). Все лимиты — константы в коде.
- По ходу — только свои тесты: `npx vitest run <файл>`. Перед сдачей задачи — `npm run typecheck`, полный `npx vitest run` и `npm run check:seams`. E2E — в задаче 16.

## Review Focus

1. **Имена файлов с пробелами, кириллицей, `-` в начале, `[`, `*`, `'`, переименования.** Ожидание: статус, diff и коммит работают с ними как с обычными. Glob не раскрывается, имя не читается как флаг. Тест — задача 11, `'коммит файла «-rf [1] Привет 'x'.txt» и переименования'`.
2. **Злой `.git/config` в папке проекта** (`core.fsmonitor`, `diff.external`, textconv, `core.pager`). Агент мог склонировать такой репозиторий. Ожидание: открытие панели и diff не запускают ничего из конфига. Тест — задача 10, `'status и diff не запускают core.fsmonitor и diff.external'`.
3. **Агент сам работает с git, пока открыта панель:** `index.lock`, файлы уже закоммичены агентом. Ожидание: понятная причина (`locked` / `stale`), список обновлён, окно не падает, лишнего не коммитится. Тесты — задача 11, `'index.lock даёт locked'` и `'путь, закоммиченный между статусом и коммитом, даёт stale'`.
4. **Огромная и грязная история:** сотни файлов, строка с картинкой base64 на мегабайты, оборванная последняя строка, файл, который CLI пишет прямо сейчас. Ожидание: сводка строится потоково за разумное время, лимиты соблюдены, на запись ничего не открывается. Тест — задача 6, `'грязная история: длинная строка, битый JSON, недописанный файл'`.
5. **Испорченный `templates.json`** (правка руками, обрыв записи). Ожидание: Qclod стартует, шаблоны пусты, а битый файл сохранён рядом как `templates.json.bad` и не затёрт первым же сохранением. Тест — задача 3, `'битый файл переименовывается в .bad, а не затирается'`.

## Ручная проверка на живом CLI

Исполнитель прогоняет на установленной сборке этапа 7 с настоящим Claude Code владельца. Итоги — в журнал этапа.

1. **Сбор шаблонов на настоящей истории.**
   - Сводка: число проектов совпадает с папками `~/.claude/projects`, свежих за 90 дней.
   - «Показать, что уйдёт»: только сообщения владельца, ни одного ответа Claude и вывода команд.
   - Снять один проект — его сообщения пропали из списка.
   - «Собрать»: ответ меньше чем за минуту, предложений не больше 15. Тексты общие: без путей и имён из сообщений.
   - Отметить 2 и сохранить.
   - Новых `.jsonl` в `~/.claude/projects` нет, хэш `~/.claude/settings.json` прежний.
2. **«Остановить» во время сбора.** Процесс `claude` сбора завершился (Диспетчер задач), лист вернулся к сводке, повторный «Собрать» работает.
3. **Сбор без входа.** Выйти из Claude Code (`claude auth logout` на тестовом профиле `CLAUDE_CONFIG_DIR`) → «Claude Code не вошёл в аккаунт…».
4. **Шаблон в живом чате.**
   - `/` + буквы названия → текст вставлен, `{{…}}` выделен, набрать поверх, отправить — агент получил ровно этот текст.
   - То же через Ctrl+K в середине черновика.
5. **Git на настоящем репозитории** (отдельный тестовый).
   - Агент правит 2 файла и создаёт третий с именем `заметка [1].md` → бейдж «3».
   - Diff каждого виден.
   - Снять одну галочку и закоммитить сообщением в две строки по-русски. `git log -1` — сообщение точно то же; снятый файл не закоммичен.
6. **Git, пока агент коммитит сам.** Попросить агента сделать `git commit` и сразу нажать «Закоммитить» в панели. Ответ — `locked` или `stale` с текстом, лишнего не закоммичено.
7. **Git и хук.** `pre-commit`, падающий с сообщением → вывод хука показан под «Git не дал закоммитить:».
8. **Git на сервере** (если задача 15 пошла по исходу 1 или 2). Чат на домашнем сервере: статус, diff, коммит работают так же. Если исход 3 — кнопка неактивна, подсказка с причиной.
9. **Поиск по истории.** Фраза из ответа Claude недельной давности находится в Ctrl+K «В разговорах». Enter открывает тот разговор, лента дочитывается.
10. **Просмотр файла.** Путь в ответе агента → «Посмотреть» → файл с подсветкой, нужная строка отмечена, правка невозможна.
