# Qclod — дизайн-документ

Дата: 2026-11-07
Статус: утверждается

## 1. Замысел и зачем

Qclod — десктопное окно для Windows 11, внутри которого живёт Claude Code CLI.

Сам CLI функционально устраивает: проблема в оболочке вокруг него. Обычный
терминал на Windows плохо ведёт себя в тех мелочах, которые встречаются
каждые несколько минут работы: вставка многострочного текста разваливается,
Ctrl+C означает «прервать», а не «скопировать», несколько проектов живут в
разных окнах терминала без общей навигации, а когда агент доработал в фоне —
об этом никак не узнать. Плюс выглядит это как голый терминал.

Qclod не заменяет Claude Code и ничего в нём не эмулирует. Он запускает
настоящий процесс `claude` в псевдотерминале и даёт ему красивое,
удобное окружение: вкладки, нормальное поле ввода, работающие хоткеи,
вставку картинок, drag&drop файлов, уведомления и вызов по глобальному хоткею.

## 2. Цели

1. Весь функционал Claude Code CLI доступен без потерь — включая слэш-команды,
   `@`-упоминания файлов, Shift+Tab режимы, интерактивные меню разрешений,
   выбор из списков, прерывание по Esc.
2. Хоткеи редактирования текста работают так же, как в любом нормальном
   приложении Windows: Ctrl+V, Ctrl+C, Ctrl+X, Ctrl+A, Ctrl+Z, Ctrl+Shift+Z.
3. Многострочная вставка не разваливается на отдельные отправки.
4. Несколько проектов одновременно во вкладках одного окна.
5. Окно выглядит как продуманный продукт, а не как терминал с подложкой.
6. Вызывается из любого места системы одним хоткеем.
7. Сообщает, когда агент закончил или ждёт ответа, пока ты в другом окне.
8. Ставится одним .exe-установщиком.

## 3. Не-цели

- Собственный агентный цикл поверх Claude Agent SDK. Оболочка всегда говорит
  с настоящим CLI через pty.
- Кроссплатформенность. Цель — Windows 11. Код не должен специально
  ломаться на других ОС, но ни тестировать, ни собирать под них не нужно.
- Универсальный эмулятор терминала. В сессии запускается `claude` и только он.
  Произвольные shell-команды — не задача этого приложения.
- Сплит-экран (две сессии рядом в одном окне).
- Библиотека промптов и счётчик токенов/стоимости — явно отложены.
- Редактирование файлов, просмотр диффов, встроенный git UI.
- Аутентификация, управление ключами, настройка моделей — всё это остаётся
  за CLI; Qclod не трогает учётные данные.

## 4. Анти-цели (провал, даже если формально работает)

- **Что-то в CLI стало недоступно.** Если появилось меню, на которое нельзя
  ответить, или слэш-команда, которую не набрать — это провал, даже если
  остальное красиво.
- **Хрупкая магия.** Если переключение фокуса между полем ввода и терминалом
  угадывается эвристикой и угадывает неправильно, пользователь оказывается в
  ловушке. У любого автоматического поведения должен быть детерминированный
  ручной обход.
- **Потеря ввода.** Набранный текст не должен исчезать при переключении
  вкладок, потере фокуса или ошибке pty.
- **Тормоза.** Поток вывода агента не должен заикаться. Блюр и анимации не
  стоят падения плавности.
- **Молчаливая смерть процесса.** Если `claude` упал или не найден,
  пользователь должен увидеть понятное сообщение, а не пустой чёрный прямоугольник.

## 5. Ограничения

- Платформа: Windows 11 Pro x64. Разработка и проверка — на машине пользователя.
- Claude Code CLI уже установлен в системе и доступен как `claude`.
- Релиз — NSIS-установщик .exe, без подписи кода.
- Приложение не хранит и не передаёт никуда содержимое сессий. Всё локально.

## 6. Решения, принятые в разговоре

### 6.1 Архитектура

Electron + xterm.js. В главном процессе на каждую вкладку создаётся pty
через node-pty, в нём запускается `claude` с рабочей папкой вкладки.
Поток вывода идёт в рендерер и рисуется xterm.js. Ввод уходит обратно в pty.

UI — React + TypeScript. Рендерер изолирован (contextIsolation включён,
nodeIntegration выключен), всё общение с главным процессом — через узкий
preload-мост с явным списком каналов.

### 6.2 Окно и внешний вид

Безрамочное окно со своим титлбаром. Вкладки встроены в заголовок, рядом —
свои кнопки свернуть / развернуть / закрыть. Фон — acrylic Win11.

Настроение — «стекло / неон»:

- фон окна полупрозрачный тёмно-синий, примерно `rgba(14,16,28,.72)` поверх блюра
- основной акцент — синий `#6E8BFF`
- вторичное свечение — фиолетовый `#B07CFF`
- границы панелей — 1px, светящиеся, низкой непрозрачности
- шрифт — Geist Mono, поставляется вместе с приложением, не тянется из сети
- анимации плавные: появление вкладок, подсветка активной, выезд окна по хоткею

Тема одна — тёмная. Светлой не делаем.

### 6.3 Вкладки и сессии

- Сколько угодно вкладок, каждая привязана к своей рабочей папке.
- Ctrl+T — новая вкладка (открывает выбор папки), Ctrl+W — закрыть,
  Ctrl+Tab и Ctrl+Shift+Tab — по кругу, Ctrl+1..9 — на конкретную.
- Закрытие вкладки корректно завершает процесс `claude` и pty.
- На вкладке показывается индикатор состояния: работает / ждёт ответа / простаивает.
- Если в фоновой вкладке агент закончил или спрашивает разрешение — на вкладке
  зажигается бейдж, который гаснет при переходе на неё.
- **Восстановление:** при перезапуске приложения вкладки возвращаются с теми же
  рабочими папками, но сессии начинаются с чистого листа. `claude --resume`
  намеренно не используется.

### 6.4 Ввод — гибридная модель

Главное решение документа. Внизу окна — собственное поле ввода; терминал
над ним остаётся полноценно интерактивным.

**Две строки ввода — и это нормально.** У самого Claude Code внизу его TUI
своя строка ввода, и она никуда не денется. Мы её не прячем и ничем не
накрываем: терминал всегда виден целиком, поэтому ни одно меню Клода
физически не может оказаться закрытым нашей панелью. Вместо этого мы
разводим их по яркости — мы управляем палитрой терминала, поэтому строка
Клода рисуется приглушённо и читается как «уходящее эхо», а наше поле под
ней — яркое, со свечением, визуальный центр окна. Набранный текст виден в
обеих: в нашей как композиция, в его как то, что реально ушло агенту.

Поле ввода:

- многострочное, растёт по содержимому до разумного потолка
- Enter отправляет, Shift+Enter — перенос строки
- Ctrl+V / Ctrl+C / Ctrl+X / Ctrl+A / Ctrl+Z / Ctrl+Shift+Z работают нативно
- история отправленного: Стрелка вверх / вниз, когда курсор у края текста
- содержимое поля — часть состояния вкладки и переживает переключение вкладок
- текст уходит в pty как bracketed paste (`ESC[200~ … ESC[201~`), чтобы
  многострочный ввод пришёл одним куском

**Режим сквозного проброса для слэш-команд.** Меню слэш-команд рисует сам
Клод по мере набора, и повторять его у себя мы не будем — оно устареет при
первом же обновлении CLI и не увидит пользовательских и плагинных команд.
Поэтому как только в пустом поле первым символом набран `/`, поле
переходит в режим сквозного проброса: каждое нажатие уходит в pty вживую,
и ты видишь родное меню Клода со всеми командами, какие у тебя есть.
Режим виден по индикатору у поля и заканчивается при отправке или когда
строка перестаёт начинаться с `/` (например, всё стёр). В этом режиме
локальные история, автодополнение и undo не работают — текст живёт в CLI,
а не у нас; вставка (Ctrl+V) по-прежнему идёт как bracketed paste.

`@`-автодополнение (6.6) остаётся нашим и работает в обычном режиме.

**Передача фокуса в терминал** — три механизма, от надёжного к удобному:

1. **Явный переключатель.** Ctrl+Backquote (или другая свободная клавиша)
   переключает фокус между полем и терминалом в любой момент. Работает
   всегда, независимо ни от чего.
2. **Детерминированные правила клавиш** (см. таблицу ниже).
3. **Эвристика.** Приложение распознаёт момент, когда Клод показал
   интерактивное меню, и автоматически передаёт фокус терминалу.
   Эвристика — удобство, а не фундамент: её можно выключить в настройках,
   и при её отказе механизмы 1 и 2 полностью сохраняют работоспособность.

**Таблица приоритетов клавиш, пока фокус в поле ввода.** Правила
применяются сверху вниз, первое подходящее выигрывает. Неоднозначностей
здесь быть не должно — это ровно то место, где анти-цель «хрупкая магия»
кусается больнее всего.

| Клавиша | Условие | Что происходит |
|---|---|---|
| Esc | всегда, независимо от содержимого поля | уходит в pty (прерывание агента) |
| Esc Esc (быстро дважды) | всегда | уходит в pty |
| Ctrl+Backquote | всегда | переключает фокус поле ⇄ терминал |
| Tab / Shift+Tab | открыт попап автодополнения в поле | выбор в попапе |
| Tab / Shift+Tab | иначе | уходит в pty (переключение режимов) |
| любая печатная | поле в режиме проброса (строка с `/`) | уходит в pty вживую |
| Enter | поле в режиме проброса | уходит в pty |
| Enter | есть текст | отправка текста bracketed paste |
| Shift+Enter | — | перенос строки в поле |
| Стрелки ↑↓ | открыт попап автодополнения | навигация по попапу |
| Стрелки ↑↓ | поле пустое и приложение видит активное меню Клода | уходят в pty |
| Стрелки ↑↓ | поле пустое, меню нет | история отправленного |
| Стрелки ↑↓ | в поле есть текст | движение курсора внутри поля |
| Ctrl+C | есть выделение в поле | копирование |
| Ctrl+C | выделения нет | уходит в pty (прерывание) |

Клик по терминалу тоже передаёт ему фокус. Где фокус сейчас — видно по
подсветке рамки.

### 6.5 Хоткеи терминала

Пока фокус в терминале, приложение перехватывает и чинит:

- Ctrl+C — копирует выделенное, если выделение есть; иначе шлёт SIGINT в pty
- Ctrl+V — вставляет из буфера bracketed paste
- Ctrl+A — выделяет видимый буфер (не шлёт управляющий символ)
- Ctrl+Shift+C / Ctrl+Shift+V — копировать / вставить всегда
- Ctrl+F — поиск по буферу терминала
- Ctrl+L — очистить экран
- Ctrl +/− / 0 — размер шрифта
- выделение мышью копирует по отпусканию кнопки; средняя кнопка вставляет

### 6.6 Картинки и файлы

- Ctrl+V при картинке в буфере — изображение сохраняется в .png во временной
  папке приложения, и в сообщение подставляется `@путь` — именно в виде
  `@`-упоминания, потому что это надёжно заставляет Клода файл прочитать;
  голый путь в тексте может не сработать, и фича молча выглядела бы сломанной.
  В поле ввода на месте пути показывается компактная плашка-превью, но
  отправляется всегда реальный `@путь`.
- Временная папка живёт в userData приложения. При старте Qclod удаляет из
  неё всё старше 7 дней и, если папка переросла заданный потолок, самое
  старое сверх потолка. Вручную её чистить не нужно.
- Drag&drop файла или папки в окно — вставляет её путь в поле ввода в позицию
  курсора. Несколько файлов — несколько путей через пробел.
- `@` в поле ввода открывает автодополнение по файлам проекта: список путей
  относительно рабочей папки вкладки, с учётом .gitignore, со сквозным
  (fuzzy) поиском. Выбор вставляет `@путь`.

### 6.7 Глобальный хоткей, трей, уведомления

- Ctrl+Shift+Space из любого места системы показывает окно поверх всех и
  отдаёт ему фокус; повторное нажатие прячет. Комбинация настраивается.
- Иконка в трее: показать/скрыть окно, список вкладок, выход. Закрытие окна
  по умолчанию сворачивает в трей, а не завершает приложение.
- Системное уведомление со звуком, когда в неактивном окне агент закончил
  работу или запросил разрешение. Клик по уведомлению открывает нужную
  вкладку. Звук и уведомления можно выключить.

### 6.8 Настройки

Глобальный экран настроек: хоткей вызова, уведомления и звук, размер шрифта,
автофокус по эвристике (вкл/выкл), поведение при закрытии окна, путь к
исполняемому файлу агента, параметры запуска по умолчанию. Хранится в JSON
в userData.

**Параметры запуска задаются на двух уровнях.** Глобально — значения по
умолчанию; у каждой вкладки есть свои переопределения, потому что разные
проекты требуют разного. Переопределяются: модель (`--model`), режим
разрешений (`--permission-mode`), конфиг MCP (`--mcp-config`) и строка
произвольных дополнительных флагов. Переопределения вкладки задаются при
её создании и редактируются потом, хранятся вместе с остальным состоянием
вкладки (6.3) и переживают перезапуск вместе с рабочей папкой.

### 6.9 Состояние сессии: откуда берётся

Индикатор на вкладке и уведомления — обязательный функционал, поэтому они
не могут опираться на разбор вывода терминала. Источник — официальные хуки
Claude Code:

- `Stop` — агент закончил ход → состояние «простаивает»
- `Notification` с матчерами `permission_prompt`, `idle_prompt`,
  `agent_needs_input` → состояние «ждёт ответа»
- `PermissionRequest` → «ждёт ответа», и в уведомление можно положить
  название инструмента
- `SessionEnd` → сессия закрыта
- отправка сообщения из поля ввода → «работает» (переход делаем сами,
  не дожидаясь хука)

Хуки подаются на запуск через `claude --settings <inline JSON>`. Этот флаг
переопределяет ключи только на текущую сессию и **не трогает файлы
настроек пользователя**, что сохраняет ограничение 5.4. Каждая вкладка
получает свой JSON, в котором команда хука передаёт id вкладки обратно в
Qclod через локальный именованный канал.

Важная тонкость: `--settings` переопределяет ключ целиком, поэтому, если у
пользователя в его собственных `settings.json` есть свои хуки, Qclod обязан
прочитать их и слить со своими, а не затереть. Молча отключить чужие хуки —
недопустимо.

Запасной вариант: если хуки по какой-то причине не сработали (вкладка
показывает «работает» дольше разумного таймаута), приложение переходит на
грубое определение по затиханию вывода, и это видно в интерфейсе как
пониженная достоверность индикатора. Уведомления при этом не шлются —
лучше промолчать, чем соврать.

### 6.10 Обработка ошибок

- `claude` не найден в PATH — вкладка показывает понятное объяснение и
  кнопку «открыть настройки», а не пустой экран.
- Процесс завершился — вкладка показывает код выхода и кнопку «перезапустить»,
  сохраняя прочитанный вывод.
- Ошибка pty — логируется, пользователю показывается причина.

## 7. Объём первой версии

Полный: всё перечисленное выше за один заход, с тестами и собранным
NSIS-установщиком. Промежуточные сборки показываются по ходу.

## 8. Качество и проверка

- Чистая логика — юнит-тестами: кодирование ввода и bracketed paste,
  таблица приоритетов клавиш из 6.4, вход и выход из режима проброса,
  распознавание меню, история ввода, состояние вкладок и их сохранение,
  `@`-автодополнение, разбор буфера обмена, слияние хуков с пользовательскими.
- **Сквозные тесты гоняются против подставного агента, а не настоящего
  `claude`.** Путь к исполняемому файлу агента и так настраивается (6.8),
  поэтому в тестах подставляется маленький скрипт, который ведёт себя как
  TUI: рисует строку ввода, отвечает предсказуемым текстом, умеет показать
  меню разрешения и дёрнуть хуки. Так сквозные тесты детерминированы,
  не требуют входа в аккаунт, сети и не тратят токены.
- Против настоящего CLI — отдельный ручной чек-лист дымовых сценариев,
  который прогоняется перед сборкой релиза: запуск, слэш-команда, меню
  разрешения, прерывание по Esc, вставка картинки, многострочная вставка,
  уведомление из фоновой вкладки.
- Хоткеи, фокус и внешний вид проверяются вручную в собранном приложении.

### 8.1 Ранняя проверка рискованных допущений

Два допущения не подтверждены документацией, и обнаружить их
несостоятельность в конце разработки будет дорого. Поэтому они
проверяются крошечными одноразовыми пробами в самом начале, до того как
на них что-то построено:

1. **Bracketed paste.** Понимает ли интерактивный TUI Claude Code
   многострочный блок, обёрнутый в `ESC[200~ … ESC[201~`, как один ввод.
   Если нет — нужен запасной способ передачи многострочного текста, и это
   меняет весь слой ввода.
2. **Хуки через `--settings`.** Действительно ли инлайн-JSON доносит хуки
   до сессии, и приходят ли `Stop` и `Notification` в живом интерактивном
   режиме, а не только в `-p`. Если нет — индикатор состояния и уведомления
   придётся строить иначе, и это меняет 6.9.

## 9. Обновления приложения

В первой версии автообновления нет. Новая версия — это новый установщик,
скачанный вручную. Версия показана в настройках. Решение принято ради
простоты сборки; если понадобится, добавим позже отдельной задачей.

## 10. Оставлено на усмотрение исполнителя

- Конкретная сборочная связка (electron-vite / electron-forge и т.п.),
  структура папок, менеджер состояния, способ стилизации.
- Выбор библиотеки для хранения настроек и состояния вкладок.
- Точный способ распознавания интерактивного меню в выводе.
- Детали вёрстки, иконография, тайминги анимаций — в рамках заданного
  настроения и палитры.
- Выбор и настройка тестовых инструментов.
