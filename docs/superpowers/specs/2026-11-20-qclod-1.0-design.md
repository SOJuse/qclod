# Qclod 1.0 — спецификация

Дата: 20.11.2026. Основа: ответы владельца на опросник (145 вопросов, `.superpowers/questionnaire/`), пять исследований (`.superpowers/research/01–05`, сводка `00-svodka.md`), гайд владельца по работе с агентами (`C:\Users\sojuse\Documents\Claude_Code_ускорение_агентами.md`).

Ссылки вида «(B12)» — номер вопроса опросника, на котором держится решение. «Решение исполнителя» — то, что владелец не решал и что спек оставляет тому, кто строит, с ориентиром.

---

## 1. Зачем

Qclod — база на компьютере владельца (Windows-ПК и MacBook M3, поровну, A7). Агент работает сутками (A6), владелец уходит по делам и управляет с телефона через Remote Control в приложении Claude (B14). Работа не должна вставать на часы из-за того, что никто не ответил, кончился лимит, упал процесс или уснул компьютер. Обычная нагрузка — 1–2 вкладки и 10–15 сабагентов (A5). Подписка Claude Max (A8).

Для кого: владелец и небольшая команда друзей (A1). Интерфейс только русский (A9).

Главная мысль исследований: сторонние оболочки для Claude Code почти все умерли, главный конкурент — Claude Code Desktop, и никто не решил надёжную долгую работу на Windows. Это ниша Qclod (research 01).

## 2. Цели, не-цели, анти-цели

**Цели 1.0** в порядке приоритета владельца (A3, A4: сначала баги и UX, потом фичи):
1. Стабильность: окно не падает, сообщения не ждут конца ответа.
2. Новый интерфейс: тёмный, технический, спокойный; проекты слева; удобные карточки вопросов.
3. Автономность: агент не останавливается без причины.
4. Сабагенты: граф и таймлайн, лента каждого сабагента, переписка с ним.
5. Голосовой ввод на локальной модели.
6. Mac (DMG arm64) и SSH к серверу на обеих платформах.
7. Шаблоны промптов, Git-панель, просмотр файлов.

**Не-цели 1.0:** английский интерфейс; Linux-сборка (позже, H10); проброс портов (позже, I16); синхронизация настроек между машинами (позже, I18); плагины Qclod (позже, K9); Telegram-бот (B14: хватает Remote Control); очередь задач и автопилот (B9, B10); точки восстановления (K3); перенастройка клавиш (K7); несколько окон (K8); голос на Mac (позже, G11); озвучка ответов (G12); голосовые команды (G8); подпись установщиков (H3, L8); автообновление на Mac (H4).

**Анти-цели (A10):**
- Qclod не становится IDE или редактором кода: файлы только смотреть, не править.
- Qclod не обрастает настройками. Новая настройка появляется, только если без неё нельзя; у каждой есть разумное значение по умолчанию.

## 3. Ограничения (держатся во всех этапах)

1. Файлы настроек пользователя Claude Code (`~/.claude`, `.claude/settings*.json`) Qclod не меняет. Всё своё хранится в `userData`.
2. Автотесты никогда не ходят в настоящего агента: только фейковый SDK `tests/fixtures/fake-sdk`. Пробы на живом CLI — отдельные скрипты `scripts/probe-*.mjs`, запускаются вручную.
3. Тестовые лазейки только под `__QCLOD_TEST_SEAMS__`, релизная сборка их не содержит (`src/main/buildFlags.d.ts`).
4. Всё, что приходит из окна по IPC, проверяется в main (`src/main/tabs/sanitize.ts`, `src/main/agentIpc.ts`).
5. Qclod запускает Claude Code пользователя, а не версию, зашитую в SDK. Каждую новую возможность CLI проверять на лету (`claude_code_version`, `capabilities` в `system/init`) и иметь запасное поведение.
6. Режим «без проверок» и «авто-да» включаются только через нативное подтверждение (`confirmBypass`, `confirmAutoAllow` в `src/main/index.ts`). Это не менять.
7. Ключ роутера ИИ лежит в `.superpowers/secrets/routerai.env` (вне git). В код, коммиты и логи он не попадает.
8. Юнит-тесты по ходу работы; E2E перед релизом; в конце всей работы — внимательный полный проход по каждому этапу (L5).

## 4. Подходы (выбраны координатором, владелец отдал «как» исполнителю)

## 5. Этапы

Каждый этап — своя ветка и PR в GitHub (L2). Версия 1.0 выходит после всех этапов (L3). Перед кодом каждого этапа владелец видит его план (L4).

Промежуточных релизов нет (L3: сразу 1.0), поэтому:
- PR этапов вливаются в ветку интеграции `release/1.0`, а не в `main`;
- `main` и автообновление друзей не трогаются до выхода 1.0;
- владелец тестирует сборку из `release/1.0` после каждого этапа (рекомендация по L1).

### Этап 1. Стабильность и очередь

**1.1. Серый экран.** Окно иногда становится полностью серым: пропадают все кнопки, помогает только переоткрыть окно. Случалось после «Стоп» или после вставки текста Ctrl+V.
- Найти и устранить причину, закрепить тестом.
- Независимо от причины:
  - перехват ошибок React на корне и на каждой панели чата. Упавшая панель показывает «Что-то сломалось» и кнопку «Перезагрузить панель», остальное окно живёт;
  - в main — обработчики `render-process-gone` и `unresponsive`: окно перезагружается, черновики и вкладки сохраняются (они уже переживают Ctrl+R через `uiPersist.ts`);
  - журнал ошибок окна и main в `userData/logs/` с ротацией, чтобы следующую поломку было по чему разобрать.

**1.2. Очередь — настоящая очередь Claude Code (B17–B19).** Детали: `.superpowers/research/05-sdk-capabilities.md`.
- Сообщение уходит в CLI сразу, с `uuid`, `origin: {kind:'human'}`, по умолчанию `priority: 'next'`: агент читает его между шагами того же ответа.
- Плашка очереди над полем ввода показывает сообщения, ещё не прочитанные агентом. У каждого три действия:
  - «Отправить сейчас»: `cancelAsyncMessage(uuid)`, затем снова с `priority: 'now'` и новым uuid;
  - «Отменить»: `cancelAsyncMessage(uuid)`;
  - «Изменить»: отменить и вернуть текст в поле ввода.
- Пузырь сообщения появляется в ленте, когда CLI сообщил, что агент его прочитал (`command_lifecycle: started`).
- «Стоп» — `interrupt({cancelQueued: true})`, отменённые тексты возвращаются в поле ввода (как сейчас).
- Статус «работает / свободен» — по `session_state_changed` и `queued_turn_count`, а не только по `result`.
- Перед кодом — проба на живом CLI (раздел 7 отчёта 05): доходят ли кадры `command_lifecycle` до цикла `for await`, как ведёт себя `priority: 'now'`.
- Если версия CLI этого не умеет — остаётся нынешняя очередь Qclod.

**1.3. Мелкие баги:**
- клик по правой половине сплита делает её активной на месте, без перестановки (E1; сейчас это делает `swapPanes` в `App.tsx`);
- три исправления, уже сделанные координатором и ещё не прошедшие ревью: иконка трея (SVG не читался), проверка настроек из окна, шум в тесте. Их ревьюит проверяющий этапа.

### Этап 2. Новый интерфейс и брендинг

Направление: тёмный технический, как Cursor и VS Code (D2); только тёмная тема (D3); средняя плотность (D4); мягкие анимации (D11); шрифты Inter + Geist Mono (D12). Мокапов не делаем, сразу код (D14). Что мешает сейчас (D1): плотная шумная лента, карточки инструментов, строка статуса, правая панель, поле ввода, шрифты и размеры.

**2.1. Каркас окна.**
- Вкладки сверху убираются. Слева боковая панель «проекты → чаты» (D7, D8): каждый чат привязан к своей папке-проекту, проекты сворачиваются. Удалённые проекты помечены меткой и цветом сервера (I7).
- Что такое «чат» (решение координатора, по образцу Claude Code Desktop):
  - под проектом сверху идут открытые чаты — у них живой процесс, как у нынешних вкладок;
  - ниже — прошлые сессии этого проекта из истории Claude Code; клик открывает сессию как чат (resume);
  - «Закрыть чат» останавливает процесс, а чат уходит в список прошлых;
  - отдельный экран истории растворяется в боковой панели;
  - процессы, как и сейчас, запускаются только для открытых чатов: активного и тех, что в сплите.
- По центру — лента колонкой около 800 px (D10).
- Поле ввода плавает по центру внизу, как в чат-приложениях (D9).
- Ctrl+K ищет по всему: чаты, проекты, сессии из истории, файлы, серверы, команды (D13).

**2.2. Сплит.**
- До 4 панелей в ряд, только слева-направо (E2, E3).
- Вкладку можно перетащить в сплит (E4), ширина панелей меняется мышью (E6).
- Раскладка сохраняется после перезапуска (E7).
- Активная панель — в рамке акцентного цвета (E9).
- У каждой панели своя правая панель с контекстом, лимитами и MCP (E5).
- Одну вкладку в двух панелях не показываем (E10).

**2.3. Лента.**
- Подряд идущие однотипные действия сжимаются в строку: «прочитал 12 файлов» (D5).
- Размышления модели скрыты и раскрываются кликом (D6).
- Строка статуса и правая панель пересобираются, чтобы не шуметь. Что именно остаётся — решение исполнителя; ориентир — research 01 (Claude Code Desktop, Cursor).

**2.4. Карточки вопросов, планов и разрешений.**
- Закреплены плашкой над полем ввода, а не в ленте (C5). Отвеченные сворачиваются в строку ленты (C9).
- Несколько вопросов идут по одному, шагами (C7). Цифры 1–9 выбирают вариант, Enter отправляет (C6).
- Под вариантами всегда есть поле «свой ответ», Enter его отправляет (C1).
- Можно выбрать вариант и дописать комментарий (C2). Как это кодировать: `answers[question]` = подпись варианта, комментарий — в `annotations[question].notes`; если CLI так не умеет, «Вариант — комментарий» одной строкой (research 05).
- Запрет разрешения — с полем «почему нет / что сделать вместо». Текст уходит агенту в `message` отказа (C3).
- План можно одобрить, отклонить с комментарием или поправить его текст. Поправленный план уходит в `updatedInput.plan` (C4).
- Кнопки разрешения: «Разрешить», «Разрешить всё такое», «Разрешить до конца сессии», «Запретить» (C8). «До конца сессии» — правило в памяти сессии, на диск не пишется.
- Diff в карточке разрешения не показываем (C10).

**2.5. Брендинг (J).**
- Название остаётся Qclod (J1).
- Иконка: премиальный минимализм, стилизованная буква Q, синий и фиолетовый, свой цвет без отсылки к Claude, скруглённый квадрат, объём, градиент и стекло (J2–J7). Плоско, без Blender (J8).
- Владельцу показываем 3 варианта (J9). Генерация — через роутер (Recraft vector, gpt-image), итог доводится до чистого SVG. Из него `scripts/make-icon.mjs` собирает PNG и ICO, а также ICNS для Mac.
- Иконка трея (J10, J11): монохромная, под тему системы, на Mac — template image. На ней точка статуса: работает, ждёт тебя, ошибка.
- Экран загрузки и картинки установщика в том же стиле (J12).

### Этап 3. Агент, который не останавливается

Подробности и источники: research 02.

**3.1. Авто-ответы, только в «авто-да» (B1).**
- Вопросы Claude: через N минут Qclod отвечает сам (B2: настраивается, по умолчанию 5).
  - Выбирается вариант с пометкой «(Recommended)», если её нет — первый (B3).
  - В вопросе с несколькими вариантами — все рекомендуемые, если их нет — первый (B4).
- На карточке идёт обратный отсчёт и есть кнопки «Ответить сейчас» и «Остановить таймер» (B5).
- Таймер останавливается, как только человек начал отвечать: клик по карточке или ввод текста в ней (B6).
- Планы в «авто-да» одобряются по тому же таймеру (B7: «в авто-да автоматически всё»).
- Ответ, данный Qclod, помечен в ленте «авто» (B15).
- Вне «авто-да» разрешения по таймеру никогда не отвечаются (B8).
- Если вопрос пришёл, когда к телефону подключён Remote Control, и человек ответил там, ответ с телефона побеждает: таймер снимается.

**3.2. Продолжение без человека.**
- Процесс агента упал: перезапустить вкладку (тот же разговор, resume) и отправить «продолжай» (B11). Не больше 3 перезапусков подряд за 10 минут, потом уведомление и стоп.
- Кончился лимит подписки: ждать сброса по `rate_limit_event.resetsAt` плюс случайная пауза до 2 минут, затем «продолжай» (B12). Не больше 3 продолжений подряд без ответа человека. У недельного лимита — ждать и показать, когда сброс.
- После пробуждения компьютера переподключить Remote Control и пересчитать таймеры.

**3.3. Компьютер не спит, пока агенты работают (B13).**
- Пока хоть одна вкладка работает, ждёт человека (вопрос, разрешение, план) или ждёт сброса лимита, держать запрос «не спать» (B13: «всегда»). Иначе компьютер уснёт с открытым вопросом, Remote Control отвалится, и с телефона уже не ответить.
- Проверить на реальной машине через `powercfg /requests`, какие флаги ставит Electron. Если не те — вызвать `SetThreadExecutionState` (`ES_SYSTEM_REQUIRED | ES_AWAYMODE_REQUIRED`) самим.
- На Mac — `powerSaveBlocker` или `caffeinate`.
- Закрытие крышки ноутбука и «Сон» в меню Пуск обойти нельзя. Qclod честно говорит об этом в подсказке.

**3.4. Автозапуск.** Qclod запускается при входе в систему и восстанавливает вкладки (B21, рекомендация).

**3.5. Remote Control не теряется (решение владельца).**
- Qclod помнит, у каких чатов был включён Remote Control (в `tabs.json`), и сам включает его снова после любого перезапуска процесса: после падения, сброса лимита, автозапуска, перезагрузки компьютера.
- Чатам, которые работали, когда их прервала перезагрузка или падение Qclod, после восстановления отправляется «продолжай». Признак «работал» хранится в `tabs.json` и снимается, когда ход закончился штатно.

**3.6. Ядро автономности — общее (решение владельца по серверу, см. 6.2).**
- Всё из 3.1, 3.2 и 3.5 пишется как модуль без зависимостей от Electron: таймеры авто-ответов, ожидание лимита, перезапуск, восстановление Remote Control. Он работает и в main Qclod, и в посреднике на сервере.
- Граница: ядро получает сообщения SDK и даёт команды драйверу. Окна, уведомления и диалоги остаются в Electron-обёртке.

**Не делаем:** бэклог задач, автопилот, предохранители, журнал авто-решений (B9, B10, B16, B15). Встроенный `/goal` Claude Code и так работает, если владелец им пользуется.

### Этап 4. Сабагенты

**4.1. Где.** Внутри чата, а не на отдельном экране (F2): кнопка «Агенты» в чате открывает поверх ленты панель или модалку с сабагентами этого чата. Точная форма — решение исполнителя.

**4.2. Вид.**
- Граф и таймлайн переключателем (F1).
- В узле: тип агента, задача, статус и время (F3). В подробностях — токены и стоимость (F10).
- Граф живой: работающие узлы «дышат», связи анимированы (F8).
- Граф доступен и у прошлых разговоров из истории (F11).

**4.3. Лента сабагента.** Клик по узлу открывает ленту сабагента как отдельный чат (F4). Данные: события `task_*`, `parent_tool_use_id`, `getSubagentMessages` / `listSubagents`, `forwardSubagentText` (research 05).

**4.4. Писать сабагенту (F5).**
- SDK не даёт клиенту писать сабагенту напрямую. Поле ввода в ленте сабагента отправляет главному агенту поручение с `priority: 'next'`: «передай агенту <id/имя>: <текст>». Главный агент пишет сабагенту инструментом `SendMessage`, тот же путь продолжает законченного сабагента.
- В интерфейсе это выглядит как переписка с сабагентом, с пометкой «через главного агента».
- Если в CLI появится прямой путь, перейти на него.

**4.5. Остановка и диспетчер задач.**
- Кнопка «Остановить» у сабагента (F6) — `stopTask` для фоновых. Для сабагентов на переднем плане — то, что реально даёт CLI; исполнитель проверяет пробой.
- Фоновые агенты и фоновые команды — в одном «диспетчере задач» (F7).

**Позже (не 1.0):** команды агентов, несколько главных агентов, общающихся между собой (F9). Гайд владельца предупреждает, что для долгой работы они ненадёжны. Запуск сабагента руками — нет (F12).

### Этап 5. Голосовой ввод

Подробности: research 03.

**5.1. Движок.**
- `sherpa-onnx-node` в `utilityProcess` Electron.
- Silero VAD делит речь на фразы.
- Модели выбираются в настройках и скачиваются там же (G3, G6), в `userData/models` с докачкой и проверкой SHA-256:
  - **GigaAM v3 e2e-RNNT int8** — по умолчанию: лучший русский, есть пунктуация;
  - **Whisper large-v3-turbo** — вторая;
  - **T-one** — лёгкая потоковая;
  - **Parakeet TDT 0.6B v3** — для речи с английскими терминами.
- Видеокарта, если есть и подходит (у владельца RTX 3090), иначе процессор (G5). Как именно задействовать GPU (CUDA-сборка onnxruntime или whisper.cpp) — решение исполнителя после замеров.

**5.2. Поведение.**
- Два способа: держать клавишу и говорить, или нажать «старт», потом «стоп» (G1). Горячая клавиша работает только в окне Qclod (G10).
- Текст появляется по ходу речи (G2). Незаконченная фраза пересчитывается раз в 0,6–1 с; если не успевает — потоковая T-one как черновик.
- Голос только вставляет текст и никогда не отправляет (G9). После остановки можно продолжить говорить или печатать.
- Пунктуация и заглавные обязательны (G7). Английские термины в русской речи — словарь замен (G4).
- Пока модель не скачана, кнопка микрофона предлагает её скачать; нынешний Win+H остаётся запасным.

**5.3. Перед встраиванием** — прототип и замеры на машине владельца (i5-10600KF, 16 ГБ, RTX 3090): скорость, память, качество на русской речи с терминами. Чек-лист — раздел 9 отчёта 03.

### Этап 6. Mac и SSH

**6.1. Mac (H).**
- DMG только arm64 (H1: M3; H2), собирается в GitHub Actions на macOS-раннере вместе с Windows-релизом (H5).
- Без подписи Apple (H3): ad-hoc-подпись через `afterPack` (`codesign --force --deep -s -`), потому что electron-builder 25 не умеет `identity: "-"`. В README — инструкция «Открыть всё равно» в «Конфиденциальность и безопасность».
- Без автообновления на Mac (H4): Qclod сообщает о новой версии ссылкой на релиз.
- Правки под Mac (research 04):
  - нативные «светофоры» (`titleBarStyle: 'hiddenInset'`) и меню в строке меню (H6) — с пунктом «Правка», иначе не работают Cmd+C/V;
  - иконка в строке меню — template image (H7);
  - Cmd вместо Ctrl во всех сочетаниях (H8);
  - PATH из оболочки входа, чтобы находился `~/.local/bin/claude` при запуске из Finder;
  - отдельная ветка в `updater.ts`.
- На Mac Qclod работает и локально, и через SSH (H9).

**6.2. SSH (I), на обеих платформах (I17).**
- **Подключение:** системный `ssh` и `~/.ssh/config`, ключи, агент и jump-хосты работают сами (I2). Серверы берутся из `~/.ssh/config`, и их можно добавлять вручную (I3).
- **Вход:** ключ или пароль (I4). Пароль хранится в системном хранилище (Electron `safeStorage`) и подаётся ssh через askpass-помощник Qclod. Открытым текстом пароль нигде не лежит.
- **Новый сервер:** отпечаток ключа сервера подтверждается в интерфейсе.
- **Папка на сервере:** обзор папок по SFTP, ввод пути и недавние папки (I5). Выбрал папку — сразу открывается чат (I6).
- **Запуск агента:** Claude Code на сервере запускается через `spawnClaudeCodeProcess` и работает под аккаунтом сервера.
- **Аккаунт сервера:** в панели видны почта и тариф. Если вход не выполнен — войти прямо из Qclod: ссылка и поле для кода (I8).
- **Нет Claude Code на сервере:** сказать об этом, без автоустановки (I14).
- **Аккаунт на сервере другой**, чем на Маке и телефоне (ответ владельца). Серверного агента видно в приложении Claude только из серверного аккаунта. Поэтому работа на сервере не должна зависеть ни от Мака, ни от телефона.
- **Посредник ведёт всё сам (решение владельца).** На сервере работает не просто буфер, а безголовый хост агента:
  - он запускает Claude Code через Agent SDK на самом сервере;
  - он крутит общее ядро автономности (3.6): «авто-да» с авто-ответами по таймеру, ожидание сброса лимита, перезапуск после падения, восстановление Remote Control;
  - Qclod на Маке — клиент посредника: показывает ленту, панель и карточки, шлёт сообщения и ответы. Сообщения SDK идут в Qclod как есть, лента строится на стороне Qclod тем же `ribbon.ts`;
  - пока Qclod не подключён, посредник копит поток. При подключении Qclod дочитывает пропущенное и видит открытые вопросы с их таймерами;
  - собирается в один самодостаточный бинарник под linux-x64 и linux-arm64 (Node SEA или аналог) в том же CI. Ядро и драйвер — общий код с Qclod. Протокол между Qclod и посредником — решение исполнителя (ориентир: JSON-строки поверх ssh-канала с номерами для дочитывания).
- **Живучесть (I9, I10).** Агент на сервере переживает обрыв связи и закрытый Mac:
  - сервер — домашний Linux (I1);
  - Qclod кладёт на сервер маленький посредник в `~/.qclod/`. Он не должен требовать Node: нативная установка Claude Code обходится без Node. Подойдёт самодостаточный бинарник под linux-x64/arm64 или скрипт на том, что на сервере есть наверняка, — решение исполнителя;
  - чтобы tmux пережил выход из сессии, может понадобиться `loginctl enable-linger`; если прав нет, Qclod говорит об этом;
  - посредник живёт под tmux или как пользовательская служба systemd и переживает выход из ssh-сессии;
  - Qclod подключается к посреднику по ssh и при обрыве переподключается, дочитывая пропущенное;
  - Claude Code сам по себе не ставится (I14). Ставится и обновляется только посредник Qclod: Qclod сам копирует его на сервер нужной версии.
- **Файлы на сервере:**
  - клик по пути — просмотр прямо в Qclod или «скачать и открыть» (I11);
  - @-упоминания и поиск файлов работают по серверу (I12);
  - вставленные картинки и файлы загружаются на сервер сами (I13).
- **Терминал сервера** — вкладка с shell (xterm.js + ssh с псевдотерминалом) (I15).

### Этап 7. Фичи

**7.1. Шаблоны промптов.**
- Сохранённые шаблоны и сниппеты, вставка через `/` или Ctrl+K (K1).
- Кнопка «Собрать мои шаблоны» (свой ответ в K1): Claude читает историю промптов владельца в разговорах Claude Code и предлагает набор личных шаблонов. Владелец отмечает нужные, Qclod сохраняет их у себя. Как именно читать историю (транскрипты `~/.claude/projects/*` только на чтение) и какой моделью — решение исполнителя.

## 6. Как идёт работа (гайд владельца)

- **Порядок:** спек (этот документ) → план этапа (`superpowers:writing-plans`) → исполнение через `superpowers:subagent-driven-development`.
- **Агенты:** на каждую задачу свежий исполнитель, после него свежий проверяющий. Координатор пишет брифы, сводит результаты и ведёт журнал, но работу руками не делает.
- **Файлы:** брифы и отчёты — файлами в `.superpowers/sdd/2026-11-20-qclod-1.0/`. Журнал — `progress.md` с решениями «Ruling: что — почему — риск». Файл продолжения — на случай сжатия контекста.
- **Полосы по ресурсам**, каждая со своим `git worktree` и своей веткой. Машина — 16 ГБ, поэтому одновременно 2 тяжёлые полосы (сборка, тесты, e2e) и 1–2 лёгкие (исследование, генерация иконок, пробы). Новая тяжёлая полоса — только при 6 ГБ свободной памяти.
- **Параллельно** делаются этапы с разными файлами. Например, этап 1 (main и очередь) и поиск иконки (2.5) или прототип голоса (5.3).
- **Общие точки** сначала выделяются отдельной маленькой задачей: типы в `shared/types.ts`, каналы `shared/channels.ts`, preload. Иначе параллельные части не сойдутся.
- **Режим работы:**
  - долгие команды — в фоне, проверка не реже раза в 4 минуты;
  - субагенты не запускают своих субагентов;
  - после 3 раундов правок — свежий агент.
- **Модели** указываются явно: сильная — для архитектуры, сложной логики и финального ревью; средняя — для механики и повторных ревью.

## 7. Что проверить (каждый этап)

1. Окно не становится серым при «Стоп», вставке Ctrl+V (текст, картинка, файл), переключении вкладок и сплите.
2. Сообщение, отправленное во время работы, доходит до агента между шагами. «Отправить сейчас», «Отменить» и «Изменить» работают. После «Стоп» тексты возвращаются в поле ввода.
3. Вопрос в «авто-да» получает ответ через N минут нужным вариантом. Таймер останавливается, когда человек начал отвечать. Вне «авто-да» ничего не отвечается само.
4. После падения процесса и после сброса лимита вкладка продолжает работу сама, без зацикливания.
5. Настройки и правила пользователя Claude Code не тронуты.
6. Релизная сборка не содержит тестовых лазеек (`npm run check:seams`).

## Уточнения после планирования (20.11.2026)

Сверка планов — `.superpowers/sdd/cross-plan-check.md` (F13, F22). Текст выше не меняется; здесь — где планы от него отходят и почему.
- **2.1, процессы чатов:** после перезапуска Qclod процесс получают ещё и чаты с записью автономности («работал», Remote Control, ожидание лимита) — иначе 3.5 не продолжит работу в неактивном чате (этап 3, задача 8).

- **1.2, «Стоп» при сабагентах:** с `perTaskStopAffordance: true` «Стоп» прерывает ход главного агента, фоновые агенты работают дальше; их останавливают «Остановить» или «Остановить все», README об этом говорит (этап 4, решение 6; этап 7, задача 17).

- **6.2, обзор папок на сервере:** через посредника Qclod по тому же ssh-каналу, а не по SFTP — подсистема SFTP не нужна, а на Windows без ControlMaster каждое новое соединение — новый вход (этап 6, решение 2).
- **6.2, запуск агента на сервере:** `spawnClaudeCodeProcess` не используется — SDK работает в посреднике на самом сервере, по решению владельца о посреднике-хосте (этап 6, решение 15).
- **6.2, терминал сервера:** выдвижная панель под лентой серверного чата, а не отдельная вкладка — модель вкладок этапа 2 не меняется, а размер окна ssh узнаёт через node-pty (этап 6, решение 7).
